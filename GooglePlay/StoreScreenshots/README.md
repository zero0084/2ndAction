## 撮影環境

- **Windows の撮影用ビルド**です。開発用の透かし(Development Build)と開発用の表示(build 番号 / DEV BUILD)を出さないビルドで、ゲームの中身は製品と同じです。
- 撮影の準備に、開発用のワープ・BEST の設定・撮影用の保存を使っています。
- 撮影の時は無敵です(倒れて止まらないように)。被弾の見た目は出ます。
- 補助(製品の設定にある自動のジャンプ/攻撃)は ON です。
- 本番サーバーへの接続はしていません。マルチプレイは同じ PC の中の LAN です。

**Android との違いの確認**:
- Android エミュレーター(1080x2400 の端末を横向き、APK 365)で、同じ HUD とカードの3択を撮って比べました。
- HUD とカードの配置・大きさは同じでした。画面の高さで UI の大きさが決まるので、1920x1080 の画像は 16:9 のスマートフォンの見え方と同じです。
- 横長の端末(20:9)では、左右に景色が広く見えるだけです。
- 実機(Android の本物の端末)では撮っていません。

## Google Play の要件

| 要件 | 結果 |
|---|---|
| PNG(透明度なし 24bit)または JPEG | すべて 24bit PNG |
| 1枚 8MB 以下 | 最大 3.22MB |
| 各辺 320〜3840px、長辺が短辺の2倍以下 | 1920x1080 / 1080x1920(16:9) |
| 2〜8枚 | 横画面 7枚(+要確認1枚) |
| おすすめに載る条件(16:9、各辺 1080px 以上を4枚以上) | 満たしている |

## 撮影できなかった / 注意がある場面

- **07 マルチプレイ**(`_review/07_Multiplayer_ja.png`)
  - 2人の CO-OP(LAN)で、YOU と P2 が一緒にサイクロプスと戦う場面は撮れました。
  - ただし、マルチの状態の欄(CO-OP P1 HP… / P2…)が、左の「持ち帰り予定 MILE」の枠に重なっています。これは実際のゲームの表示です。
  - マルチでは BEST が 0.00m と表示されます。走り出し(Lv.1、18km/h)の場面です。
  - **表示の重なりを直すまで、正式採用はおすすめしません**(直すかどうかはマスターの判断)。
- **縦画面**(`portrait/ja/`)
  - この PC の画面は高さ 1080 なので、1080x1920 の窓を作れません。608x1080 の窓を2倍の解像度で撮って、1080x1920 に縮めています。
  - そのため UI は、1080 幅の実際の端末より約18% 大きく見えます。Android とは見え方が少し違うので、**確認用の候補**です。
  - 縦画面のプレイ中は、走る場所が画面の下で、キャラが小さく見えます。縦画面で良いのは「カードの3択」(説明がよく読める)と「キャラクター選択」です。
- **キャラの大きさ**: 横画面でも、主人公は 1080p の画面で 60〜80px ほどです。ゲームの実際の見え方のままにしています。

## 撮り直し方(開発用)

- 撮影用ビルド: Unity メニューの BuildStoreCapture(`BuildStoreCapture.Build`)
- 横画面: `-storeCapture <dir> -scShots run_wasteland,aerial,cards,cave,sky,charsel,boss ... -scLang ja|en`
  - 1920x1080 の枠なしの窓(`-popupwindow`)、元のファイルは `stills/`
- キャラ選択: `-scShots charsel [-scCharAt ninja]`(新規)
- 縦画面: 608x1080 の窓で `-scSuper 2`(静止画だけ2倍の解像度、新規)
- マルチ:
  - 撮影用ビルドを2つ起動します。HOST は `-netAutoHost -netAutoShotDir <dir> -netAutoAuraLog 秒,...`、JOIN は `-netAutoJoin lan`。
  - どちらにも `-scClean -netAutoMode coop -netAutoStartHp 50` を付けます。
  - `-scClean` は開発用の表示を出さない指定です(新規)。
