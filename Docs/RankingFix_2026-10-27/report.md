# ランキング「脱出しても記録がありません」の修正(2026-10-27)
nAPK 387(開発版、development へ接続): `Unity/2ndAction/Builds/Android/2ndAction.apk`

APK 386(development)の実機で、ソロで脱出 → ホーム → ランキングを開くと「記録がありません」と出た件。

## 原因

送信そのものは成功していた。**ランキングの画面が、送信より先に終わった読み込み(空の表)を出し続けていた。**

1. 脱出の確定で、記録は「送信待ち」に入る(この時点では送らない)
2. ホームに戻ると、送信待ちの送信が始まる
3. すぐにランキングの画面を開くと、画面は表の読み込みを始める。送信は「すでに送信中」なので待たない → 読み込みと送信が並んで走る
4. 読み込みが先に終わる → サーバーにはまだ記録が無い → 「記録がありません」
5. 送信が終わっても、画面は読み直さなかった(20秒の間は前に読んだ表を使う)

アプリを起動し直すと記録は出ていた(クラウドには正しく載っていた)。
加えて、前のランの送信から30秒以内だと、ホームでの送信が最大30秒遅れることがあった。

## 修正箇所

- `Online/Leaderboard.cs`
  - サーバーが返事をした送信の数 `SentVersion` を追加
  - 資格のある成功を確定した時に、次のホームで**すぐ**送るようにした(30秒の間隔を待たない)
- `Online/RankingPanel.cs`
  - 送信が終わったら(`SentVersion` が変わったら)今のマップの表を読み直す。ほかのマップの古い表は捨てる
  - 読み込みの途中で送信が終わった時は、読み込みが終わってからもう一度読む。送信の後の読み直しは、連打防止の2秒の制限を受けない
- 試験: `QaSweep.RankRoute.cs`(`-qaRankRoute <dir> -rrPhase run|reopen [-rrHomeWait 0] [-rrMeters N]`)
  - 実際の経路で確かめる: ホームの START → 普通に走る(ワープ・無敵なし)→ 長押しの脱出 → RESULT → 「ホームへ」(タップ)→ ホームのランキング → 起動し直してもう一度
  - 脱出は本来最初のボスの撃破で解放されるので、試験では指定の距離まで普通に走った後に解放だけしている。記録の対象外の印は付かず、確定とランキングは本物の経路を通る

## 確認(development の本物の Unity Cloud、Windows の試験用ビルド・専用の保存)

| 確認の点 | 結果 |
|---|---|
| 1. 脱出の成功で送信の処理が呼ばれるか | 呼ばれる(確定 → 送信待ちに入る → ホームで送信)。直す前もここは正常だった |
| 2. 送る距離 | 確定した到達距離と同じ(368.9m を走って 368m。小数は切り捨て) |
| 3. マップ / ランキングの ID | `wasteland_road` → `omm_best_wasteland_road`(今の4マップの設定と一致) |
| 4. Player ID | 送信の時と読み込みの時で同じ |
| 5. UGS の環境 | 送信・読み込みとも development |
| 6. 送信の返事 | Accepted(受け付けた) |
| 7. エラーコード | 送信は失敗していない。失敗は画面の読み直しが無いことだった |
| 8. ローカルの印だけ先に変わっていないか | 送信待ちはサーバーの返事の後に消える(Accepted を確かめてから送信済みにする) |
| 9. 実際の脱出・RESULT の経路 | 上の試験で、直す前に再現した(送信は Accepted なのに、画面は30秒後も「記録なし」) |
| 10. 起動し直した後の My Best / My Rank | 出る(直す前も出ていた。クラウドには載っていたため) |
