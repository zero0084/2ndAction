# Steam ストア素材 制作計画(2026-10-23 調査結果)

## 調査で分かったこと
- 開発版(Development Build)の画面には、Unity が描く「Development Build」の透かしが必ず出る(消せない)。画面下の「build …」の表示もラン中に出る。→ 素材は開発版では撮れない
- 既存の撮影の仕組み(-qaAerialVideo / -qaTapVideo / EncounterDemoCapture など)は 30fps の静止画の連番だけで、音は録れない(音は実時間で鳴るので、固定のフレームの速さで撮ると音がずれる)
- ゲームの BGM/SE は、このプロジェクトのスクリプトで作った音(Tools/audio/gen_audio*.py。権利はプロジェクトのもの)。ファイルの説明は「仮音源」
- ネタバレ: ラスダン(last_corridor)・死神三姉妹(各マップの 100,000m)・エンディング。開発版ではステージ選択にラスダンが見える
- 製品版でもある仕組み: 自動前進・オートの補助(高速時のジャンプ/攻撃)・CPU サポート・闘技場(ボスとの練習)・BONUS ZONE

## 撮影の方法(案)
1. **撮影用ビルド**(新規、製品版とは別): 開発版ではない Windows ビルドに、撮影用の記号(OMM_CAPTURE)を付けた時だけ「撮影の進行役(CaptureDirector)」と必要な開発用の機能(距離ワープ・ボスの配置・カード選択を出す・入力の代行)を入れる。製品版のビルドにはこの記号を付けないので、コードも動きも入らない
   - 透かし・DEV 表示・TEST DATA・DEBUG ボタンは出ない。撮影中は「build …」の表示も消す
2. **撮影の台本**(JSON): ショットごとに キャラ / マップ / 距離 / 速さ / 敵の並び / ボス / 入力の流れ(またはオートの補助)/ 撮る秒数 を書く。同じ台本で何度でも同じ場面を撮り直せる
3. **映像**: 1920×1080、60fps を固定のフレームの速さで書き出し(処理が重くてもコマ落ちしない)。**音**: Unity の AudioRenderer で同じ時間の流れの音を書き出し → ffmpeg で H.264 + AAC
4. **編集**: ffmpeg で切り出し・つなぎ・フェード。字幕(短い説明)とロゴの最後のカードは、文字の表(日本語/英語)から作った透明 PNG を重ねる → 文字を変えても作り直せる
5. **システム紹介の画像**: 実際の撮影画像 + 説明の文字を、レイアウトの定義(JSON)と文字の表(ja/en)から Python で合成。短いアニメーションは撮影の連番から GIF/WebM
