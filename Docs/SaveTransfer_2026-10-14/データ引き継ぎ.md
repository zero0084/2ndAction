# データ引き継ぎ(書き出し・読み込み)— 2026-10-14

機種変更に備えた**手動の**引き継ぎです。クラウド同期・アカウント連携は含みません。まず Android で使えます。ファイルの形は機種に依存しないので、iPhone / PC でも同じファイルを読める作りにしています(**iPhone との相互移行は未確認**)。

- 実装: `Save/SaveTransfer.cs`(書き出し・検査・置き換え・途中終了からの復旧)、`Save/SaveTransferUi.cs`(画面と入出力)、`Plugins/Android/SaveTransferBridge.java`(Android 標準の保存先/ファイルの選択)、設定の「データ引き継ぎ」(`Settings/SettingsPanel.cs`)
- 確認用(開発版だけ): `Dev/FileSaveStore.cs`(`-fileSave`: 保存を専用のファイルへ。通常のセーブに触れずに再起動を確かめる)、`QaSweep.Transfer.cs`(`-qaTransfer`)
- APK: 309(最終。エミュレーターの確認は 308 で実施。309 との違いはランキング/広告/課金の修正と文言で、引き継ぎの処理は同じ)

## 1. 使い方

1. ホーム → 設定 → 「データ引き継ぎ」
2. **書き出し**: 「ファイルに書き出す」→ Android の保存先の選択(ダウンロード / Google ドライブ / SD カードなど)→ 保存。ファイル名は `OneMoreMile_save_年月日_時分.json`。
   - 書いた後に読み直して、同じ中身か確かめます。
   - ファイルには保存日時とアプリの版が入ります。
3. 新しい端末で: 設定 → 「データ引き継ぎ」→ 「ファイルから読み込む」→ ファイルを選ぶ。
4. 確認の画面が出ます。
   - 上に保存日時とアプリの版。
   - その下に、**ファイル**と**今の端末**を並べた表(所持MILE、カード(種類/枚数)、デッキ、解放したマップ/キャラ、最高距離、累計距離、LAST CORRIDOR)。
   - 注意書き:「今の進行は、このファイルの内容に置き換わります。合算はされません」「この端末の中断中のランは破棄されます」(ある時だけ)「設定・広告なしパス・ランキングの登録は引き継がれません」。
5. 「**現在の進行を置き換える**」で読み込み、画面を読み直して「データの引き継ぎが完了しました」。「キャンセル」なら何も変わりません。

- 設定の画面にも、短い案内を出しています:「端末の故障に備えるには、書き出したファイルを別の端末やパソコン、外部ストレージなどに保管してください」。
- 引き継ぎは**ホームでだけ**できます。ラン中・マルチ接続中・闘技場・練習ではボタンが押せず、理由を出します。
- PC/Editor では、保存先の選択画面の代わりに `persistentDataPath/SaveTransfer/` へ書き出し、そこにある一番新しいファイルを読み込みます。**PC 版の正式なファイル選択の画面は未実装**です。

## 2. 引き継ぐ物 / 引き継がない物

**引き継ぐ物**: セーブの登録表(`Save/SaveKeys.cs`)で「進行」に分類されたキー全部と、マップ別の進捗キー。ただし下の「引き継がない物」は除きます。
- 新しい進行のキーを登録表に足せば、自動で対象になります。

| 分類 | キー(主な物) |
|---|---|
| 所持MILE | TotalOwnedMile |
| カードと強化 | OwnedCardsV1(所持カード・合成カード・Lv・枚数)、CardMasteryV1(Mastery/AWAKENED)、NewUnconfirmedCardsV1、CardDataFormat |
| デッキ | DeckCardIds、CharacterCardSlots.<キャラ>(キャラごとのキャラカード枠) |
| 解放 | UnlockedStagesV1、UnlockedCharsV1、UnlockedIds、FinalDungeonUnlocked、SprintGatesV1、UnlockRulesV1、解放のお知らせの確認済み/一覧で見た印 |
| 記録 | BestDistance、BestTime、BestDistance_v2_<マップ>(マップ別BEST)、RunReachV1_<マップ>、LifetimeDistance、死神三姉妹/マップ別の死神との遭遇、BossSeenV1、確定したランの ID(CommittedRunsV1) |
| その他の進行 | 選択中のキャラ/ステージ、コードネーム(表示名。ID ではない)、チュートリアルの進み、デッキ枠の案内、広告/パスの報酬の記録(MILE 2倍にしたランの ID・広告ガチャの日付と回数) |

**引き継がない物**

| 物 | 理由 / 読み込み先での扱い |
|---|---|
| 設定(音量・画面の向き・揺れ・補助・言語・オーラ・マルチの設定など) | 端末ごと。読み込み先の値のまま |
| 開発用の値・管理情報(形式の版・リリース世代) | 端末ごと。形式の版はファイルに別に持つ |
| 中断中のラン(CONTINUE) | 対象外(ホームで引き継ぐ仕様)。**読み込み先の中断データは消す**(古い進行のランが残らないように) |
| 確定の途中の控え(PendingCommitV1) | **読み込み先の控えは消す**(後から古い MILE が足されないように) |
| ランキング: 参加の同意・投稿待ち・資格のある自己ベスト・送信済み | 端末のアカウント(匿名サインインの ID)に結びつく。**読み込み先の値のまま** |
| 認証の ID・セッション | ゲームの保存には無い(各 SDK が持つ)。ファイルに入らない |
| 広告なしパス | ストアのアカウントの権利。新しい端末では「購入を復元」で戻す |

## 3. ファイルの形と安全の仕組み

- UTF-8 の JSON:
  - 形式名 `OneMoreMile.SaveTransfer`、形式の版 `formatVersion`(今は 1)
  - 保存日時(UTC と端末の時刻)、アプリの版、書き出した機種
  - セーブ形式 `saveSchema`、リリース世代
  - 要約(確認の画面に出す値)、項目の一覧(キー・型・値)、検査値
- **読み込む前にファイル全体を検査**して、どれか1つでも合わなければ拒否します。拒否した時、今のデータは一切変えません。
  - 形式名、形式の版、セーブ形式、リリース世代。開発版と製品版の間では引き継げません。
  - 検査値と項目の数。
  - キーごとの型と、値の範囲:
    - MILE は 0〜20億
    - 距離は有限で 0 以上
    - カードは実在して Lv1〜9
    - デッキは 12 枚以内で実在のカード
    - マップ/キャラは実在の物
    - Mastery の★は 0〜5
    - JSON は閉じていること
  - 必要な項目(MILE・累計距離・解放の印)があること。
  - 要約と中身が一致すること。
- 新しい版のファイル(形式の版やセーブ形式が新しい、知らないキーがある)は「アプリを更新してから」と案内して拒否します。古いセーブ形式のファイルは、読み込んだ後に今の形式へ移行します。
- **読み込みの手順**(新旧が混ざらないように):
  1. 読み込みの直前の全データを `pre_import_<日時>.json` に控える(5世代)。
  2. 適用する内容を `import_pending.json` に書き切る(一時ファイルに書いてから置き換え)。
  3. 置き換える:
     - ファイルの値を書く。
     - ファイルに無い引き継ぎのキーは消す。
     - 中断データと確定の控えも消す。
     - 1回の保存で書き切る。
  4. `import_pending.json` を消し、起動時と同じ処理を流す(形式の移行・検査・正常な控えの更新・読み直し)。最後にシーンを読み直す。
- **途中で落ちたら**: 次の起動の一番最初に `import_pending.json` があれば、同じ内容を最後まで適用します(何度適用しても同じ結果)。②より前で落ちた時は何も変わっていません。
- **古い進行が戻らない / MILE が二重に足されない**:
  - 読み込み先の確定の控えは消します。
  - 「消失したらバックアップから戻す」仕組みは、進行のキーが1つも無い時だけ動きます。読み込みの後は正常な控え(lastgood)が読み込んだ進行になります。
  - 開発版のデバッグランの控えが残っていれば別名へ移します。
  - 置き換えなので、同じファイルを何度読み込んでも同じ結果です。

### 改ざんの検出と、その限界
- 検査値は HMAC-SHA256 です。鍵はアプリの中にあります。
- **検出できる物**: 壊れたファイル、途中で切れたファイル、手で値を書き換えたファイル、項目を足した/消したファイル。
- **限界**: アプリを解析して鍵を取り出せば、正しい検査値の付いたファイルを作れます。**ファイルの検査だけでは不正対策は完了していません**。
  - 値の範囲の検査で、あり得ない値(負の MILE、Lv10 以上のカードなど)は弾きます。
  - ただし「あり得る範囲で多い MILE」は防げません。
- ランキングへの影響:
  - 引き継いだ記録(BEST など)は、ランキングへ投稿しません。投稿されるのは、その端末で成功したランだけです。
  - 不正対策の本体はサーバー(Cloud Code)の検査です。

### ランキングでの扱い(確認した内容)
- ランキングの ID は匿名サインインの ID で、端末の SDK が持ちます。ファイルには入らず、引き継ぎません。
- 新しい端末は別のプレイヤーとして扱われます。
  - 前の端末の掲載中の記録は、サーバーに前の ID のまま残ります。
  - 新しい端末の ID には、何も載っていない状態から始まります。
- 新しい端末で参加(同意)すると、その端末で確定した記録だけを送ります(投稿待ち・自己ベストは端末ごと)。
- 引き継いだ BEST 自体は送りません。ローカルの BEST の表示と、疾走出発の行き先には使います。

## 4. 確認の結果

普段のセーブ(Windows のレジストリ / Android の通常の保存)は使っていません。保存は専用のファイル(`-fileSave`)だけです。Windows はレジストリのゲームのキー 70 個が、試験の前後で同じであることを確かめました。

### Windows(開発版、本当の再起動を含む)
| 試験 | 結果 |
|---|---|
| 書き出し(A: MILE 123,456 / カード 3種6枚 / デッキ3 / マップ3 / キャラ4 / BEST 23,456m / 累計 345,678m) | 合格。ファイルに中断データ・確定の控え・ランキングのキー・設定/開発用/管理のキーが入っていない |
| 既存の進行(B: MILE 999・中断中のラン・ランキングの投稿待ちあり)へ上書き | 合格: 引き継ぎのキーが A と完全に一致。MILE 123,456。B の中断データは消え、B のランキングの投稿待ちは残る |
| 読み込み直前に古い確定の控え(MILE +500)を置いた状態から | 合格: 控えは消え、+500 は足されない |
| キャンセル(確認の画面まで → キャンセル) | 合格: 何も変わらない(中断データも残る) |
| 壊れた/不正なファイル 19 種 | 全部拒否、今のデータは変わらない、読み込みの控えも書かれない(空 / JSON でない / 他の JSON / 途中で切れた / 値を書き換えた / 項目を消した / 形式の版 2 / セーブ形式 4 / 世代違い / 未知のキー / 設定のキー / MILE 負 / カード Lv15 / 存在しないカード / 距離 NaN / 壊れたカードの JSON / MILE が無い / 要約の書き換え / 型の書き換え) |
| 読み込みの途中の強制終了(4か所: 控えを書く前 / 適用の前 / 適用の途中(半分を書いて保存した状態)/ 保存の後) | 合格: 控えを書く前 → B のまま。他の3つ → 次の起動で A に揃う(混ざらない) |
| 読み込みの後の複数回の起動(3〜4回) | 合格: 毎回 A のまま。MILE は増えない。確定の控えも途中の控えも残らない |
| 同じファイルをもう一度読み込む | 合格: A のまま(カードも MILE も足されない) |
| 古いアプリ(セーブ形式 2)のファイル | 合格: 読み込んだ後に形式 3 へ移行(Mastery の記録を作る) |
| Android で書き出したファイルを Windows で読み込む | 合格: 読み込んだ後の進行が、ファイルの全項目と一致。MILE もファイルの値 |

### Android エミュレーター(Android 15、APK 308)
| 試験 | 結果 |
|---|---|
| 書き出し: 標準の保存先の選択(ダウンロード)→ 保存 | 合格: 書いたファイルを読み直して一致(verified)。中身は正しい B |
