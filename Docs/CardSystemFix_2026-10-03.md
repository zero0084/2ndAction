# カードシステムの正常化(2026-10-03)

今回は「数値バランスを決めなくても直せる不具合・基盤」だけを対応した。
次のものは変えていない。

- 91枚のカードの数値
- 敵HP / ボスHP
- 10倍スケール
- MILE報酬量
- SPEED UP等の倍率
- VAMPIREの確率
- ATTACK系の増加量
- Final Evolution

最新コードは main `d2dc987` を確認してから作業した。

## 1. Lv9上限を突破できる問題

**原因**

Lv9の上限(`GameManager.GetCurrentRunStack`)を「カードIDの文字列」ごとに数えていた。
同じ能力でも、次の表記はそれぞれ別のIDなので、別々にLv9まで入った。

- 素のカード `attack_up`
- 合成カード `v2|attack_up|9|1|attack_up*9`
- レア度だけ違う `v2|attack_up|9|2|…`
- 旧形式の複合ID `attack_up+speed_up`

キャラカード3枠とラン中の取得を合わせると、同じ能力を最大117回分重ねられた。

**修正**(`GameManager.CardCap.cs`)

- ラン中に実際に適用した回数を、能力(元カードの cardId)ごとに数える。
- どの経路でも、1つの能力は合計9回分までしか適用しない。対象の経路は次の4つ。
  - キャラカード枠(ラン開始時)
  - レベルアップ / ボス報酬の取得
  - CONTINUE の再適用
- カードIDは能力に分解して数える。
  - 合成カード: 能力 × 強化量
  - 旧形式の複合ID: それぞれの能力
- 合成カードは能力ごとに、空きのある分だけ効く。
  - 例: 攻撃×5/速度×4 の合成を攻撃Lv9の状態で取ると、速度の4回分だけ効く。
- 候補に出すか / 表示のLvは、そのカードの主能力のLvで決める。
  - Lv9に届いたら候補から外れる。
  - 表示は「Lv.N → Lv.N+1」で、9で止まる(MAX)。
- 1回分の効果の値は変えていない。
- CARD BALANCE TEST などの開発ツールは、従来どおり上限なしで掛けられる(数値の確認用)。

## 2. キャラカード / デッキ / 合成の上限処理(判断をお願いしたい点)

**今の仕様(10/02から)**

- 「ラン中のカードLv = キャラカード枠のLv + ラン中に取得したLv、上限9」。
- デッキ10枚は、レベルアップ候補の山。デッキに入れただけでは効果は出ず、取得した時に効く。
- 今回は、この仕様を「カードID」ではなく「能力」で数えるようにしただけ。

**仕様として確認してほしいこと**

同じ能力を、キャラカードの複数の枠に入れた場合の扱い。

- 例: ATTACK UP Lv9 を2つの枠に入れる。
- 以前は Lv18 相当まで効いた(表示もLv18)。
- 今は合計9で止まる。装備自体はできるが、2枚目は効かない。
- 「Lv10以上にはならない」という基本仕様に合わせて9で止めた。

キャラカードは別枠として扱い、9を超えてよい仕様にする場合はお知らせください。
その場合は次のように分けられる。

- 案A: キャラカード枠の中だけは上限なし。
- 案B: キャラカード枠とデッキの取得を、それぞれ9まで。

装備画面で同じ能力を重ねられないようにする案もある(UIの変更が必要。今回は未対応)。

## 3. MOMENTUM / OVERDRIVE が距離依存になっていた原因

**原因**

- 攻撃の加算は `MomentumBonus × (GetSpeedMultiplier() − 1)`。
- `GetSpeedMultiplier()` は「走行距離による自然加速」だけを返す関数だった。
  - 100mごとに+5%の複利。
  - 3.6km以降は常に×5.556。
- 速度カード(SPEED UP等)やキャラの走る速さは、別の値(`runSpeed`)に掛かっていて、この式には入っていなかった。
- 結果として、実際の速さとは無関係に、距離で決まる値になっていた。

**今回の対応**

攻撃の数値は変えていない。既定は従来の式のまま。

- `PlayerController.MomentumSpeedTerm`: 速度の項を1か所にまとめた。
- `MomentumUsesCurrentSpeed = true` にすると、「実際の現在速度 ÷ 基準18km/h − 1」に切り替わる。
  - 次の数値調整で、式ごと決める想定。

## 4. 現在速度を参照できる仕組み

- `PlayerController.CurrentRunKmh`
  - HUDの km/h と同じ値。
  - 中身: 距離による自然加速 × キャラの走る速さ × 速度カード、安全上限900km/h。
  - 次の一時的な動きは含めない(攻撃のたびに揺れないように)。
    - 攻撃の踏み込み / ノックバック
    - 被弾で止まった一瞬
- `SpeedFactor01(from, to)`
  - 0〜1の正規化。例: `SpeedFactor01(50, 150)` で 50km/h=0、100km/h=0.5、150km/h=1。
- 50 / 75 / 100 / 125 / 150km/h を正しく取れることを、自動テストで確認した(下の「テスト」)。

## 5. Spawn Rate(敵出現率)が無効だった原因

- カードの値は `GameManager.EnemySpawnRateMultiplier` に入っていた。
- 読んでいたのは、旧来の EnemyWallManager(マイルストーンの壁)だけだった。
- 全4ステージが EncounterDirector に置き換わり(`replacesMilestoneWalls`)、壁は止まっていた。
- その結果、次の出現率の部分がどこからも使われていなかった。
  - MORE ENEMIES / HORDE
  - GREED / FAST ENEMIES / MONSTER RUSH / HELL MODE / NO TURNING BACK / PANDEMONIUM

## 6. EncounterDirector への反映方法

出現率を「Encounterの頻度」に変える。

**変えるもの**

- Encounterどうしの間隔 ÷ 頻度。
- 休憩(Rest)区間の長さ ÷ 頻度。
- 合流の後の間隔 ÷ 頻度。
- Restを選ぶ割合 ÷ 頻度。

**変えないもの**

- 1つのEncounterの中身(Formationの敵の数・並び)。敵が1か所に重ならない。
- ボスの関門・ボス戦中の停止・BONUS ZONE・安全区間。いずれもこのDirectorの外の仕組み。
- 上下ルートの分岐区間。地形の分岐の位置で決まるので、出現率では増えない(荒野街道では効き方が小さい)。

**上限・マルチ**

- 頻度は ×0.5〜×2.0 で止める。
  - 調整は EncounterDirector の `spawnRateMaxFrequency` / `spawnRateMinFrequency`。
  - PANDEMONIUM Lv9(×6.4)のような値でも、間隔は半分まで(端末の負荷)。
- マルチでは、出現を決める HOST のカードの値を使う。JOIN のプレイヤーのカードは効かない(仕様の確認待ち)。

## 7. 属性システムの基盤設計

**基本の考え方**

- 属性はカードの取得でだけ付く。
- キャラ固有の属性、敵の属性・弱点・耐性、相性表は作っていない。

**構成**

- `EffectType` に属性の値を21種類追加した。
  - 番号で保存されるので、末尾に追加した。
  - 値は加算で重なる。
- `ElementType` に Blood を追加した。
- ファイルの役割:
  - `Elements/ElementStats.cs`: ラン中の値。
  - `Elements/ElementSystem.cs`: 命中時の判定。
  - `Elements/ElementStatus.cs`: 敵1体ごとの状態。
- 判定する場所: 敵/ボスへの命中はすべて `PlayerAttackInfo.ScaleDamage` を通るので、そこで判定する。
  - 全キャラ・全技・飛び道具に同じく乗る。
- 追加のダメージ(継続ダメージ / 落雷)は「静かなダメージ」で入れる。
  - のけぞり・音・ヒットストップ・コンボ数は起こさない。
  - そのダメージ自身からは属性を判定しない(無限に連鎖しない)。
  - 倒れた時は通常の撃破と同じ扱い(経験値 / MILE / BONUS ZONE の数え方も同じ)。
- 重ねがけは「時間を延ばし、強い方の威力を残す」。足し算で際限なく強くはならない。

**属性ごとの役割と設定できる値**

| 属性 | 役割 | 設定できる値 |
|---|---|---|
| 炎 Burn | 命中した敵が燃え続ける(0.5秒ごとの継続ダメージ) | BurnChance / BurnPower(その命中のダメージに対する1秒あたりの割合)/ BurnDuration |
| 氷 Chill / Freeze | 行動が遅くなる。重なると凍結 | ChillChance / ChillSlow / ChillDuration / FreezeStacks / FreezeDuration |
| 雷 Lightning / Chain | 当たった敵へ落雷+近くの別の敵へ連鎖 | LightningChance / LightningPower / LightningChains / LightningRange |
| 風 Wind | 前方へ飛ぶ貫通の風刃、飛び道具の貫通の追加 | WindBladeChance / WindBladePower / WindPierce / WindRange |
| 血 Bleed | 出血の継続ダメージ、その一部を回復、低HPほど強い | BleedChance / BleedPower / BleedDuration / BleedLifesteal / BloodLowHpBonus |

氷の効き方:

- 雑魚: 移動・予備動作・攻撃の間隔がゆっくりになり、凍結すると止まる(新しい攻撃も始まらない)。
- ボス: 止めない。
  - Chill は鈍化の0.35倍。
  - Freeze は「待ち・予備動作が0.5倍の速さ」に変換。
  - 並走の速さは変えない。
  - 効くのは荒野/洞窟/天空のボスだけ。ドラゴン / 魔人への氷は未対応。

その他:

- 「どの敵が何の状態か」は、頭上の小さな印で見える。色は炎=橙、出血=赤、冷気=水色、凍結=白(仮の見た目)。
- マルチ: 敵のHPを持っている端末(シングル / HOST)でだけ判定する。JOIN のプレイヤーの命中には、今は属性が乗らない(今後の課題)。

## 9. VAMPIRE / 血属性(構造の確認のみ)

**今の吸収の仕組み**

- 敵 / ボスを倒した時に、確率 `lifestealChance` で `lifestealAmount` を回復する。
- 確率は全カードの合計。
  - そのため、VAMPIRE 1枚(0.15/Lv)でも Lv7 で100%に届く。
  - PREDATOR は Lv5、PHOENIX は Lv4 で100%。

**目標の構造(VAMPIRE=入口 → PREDATOR=確率 → OVERHEAL=回復量 → BLOOD RUSH=低HP → PHOENIX=上位)は実装できる**

例えば次のように作れる。

- 吸収は VAMPIRE を持っている時だけ発動する。他のカードの確率は VAMPIRE がある時だけ加わる。
- 確率に上限を設ける。
- 命中時の吸収(血属性の BleedLifesteal)と、撃破時の吸収を分ける。
- BLOOD RUSH の低HP補正は、血属性の `BloodLowHpBonus` と同じ考え方で作れる。

今回は確率・回復量を変えていない。

## 10. タイタン / 魔人(近接キャラが攻撃できない)

**原因**

- タイタン(天空20km)
  - 距離: 常にプレイヤーの5〜14m前に立つ(minGap=5)。
  - 当たり判定: 被弾範囲は胸〜肩(地面から約0.6〜5m)で、高さは届く。手前の端は常に数m先。
  - 近接キャラの射程: 間合いが届かない。
  - 移動: 近づく攻撃が無い。
  - カードなしの近接4キャラは、300秒で0ダメージだった。
- 魔人(天空5km)
  - 距離: 常にプレイヤーの約10〜18m前を漂う。
  - 移動: 近づく行動が無い。
  - 近接キャラは、跳ね返した火球でしか当てられなかった。

**対応**(HPは変えていない)

- タイタン
  - 2回の攻撃ごとに「膝をつく」行動を入れた。
  - 身をかがめて回廊のすぐ前まで寄り、拳を振り下ろす(予告あり)。
  - その後3.2秒、低い姿勢のまま隙を見せる。被弾範囲の手前の端がプレイヤーの0.8m先に来る。
- 魔人
  - 2回の攻撃ごとに、攻撃の後で地面近くまで降りてくる。体の手前の端がプレイヤーの0.8m先。
  - 2.8秒とどまる(暗い色=今は撃ってこない)。
- 調整はタイタンの `kneel*`、魔人の `expose*` で行える。

## 11. 攻撃の適用の不一致(調査結果)

**修正したもの(明らかなバグ)**

- 拳銃士の弾がボスを貫通していた。
  - 荒野/洞窟/天空のボスの被弾範囲は子の `BossHurtbox` にあり、弾が見つけられていなかった。
  - 弾のコメント自体に「貫通させない」と書かれていた。
  - ダメージは元々1回で、弾が後ろの敵にも当たり得た。
- 弓/魔法/忍者/巫女などの飛び道具(KitProjectile)が、ボス・敵の「攻撃判定」に触れただけで消えていた。
  - 攻撃判定は持ち主の子なので、「当たった」扱いになり、ダメージ0で消えていた。
  - 攻撃判定は素通りするようにした。

**ゲーム性が変わるので、変更せずに報告するもの**

- 初撃 / 締めのカードが弓 / 魔法 / 忍者 / 巫女に乗らない。
  - これらのキャラは連撃の段を数えない(comboCount が0のまま)。
- 初撃 / 締めのその他の不揃い:
  - お嬢様騎士は毎回、初撃と締めの両方が乗る(連撃1段)。
  - 竜騎士は締めが2段目と3段目に乗る(maxComboChain=2、実際は3段)。
  - 連撃以外の技に、直前の連撃の段が残る。
  - 直すとダメージが変わるので、キャラごとの仕様を決めてから直すのがよい。
- 範囲カードが、飛び道具(弾 / 矢 / 魔法 / 札 / 手裏剣など)に乗らない。
  - 範囲は「近接の判定の大きさ」に掛ける設計。
  - 飛び道具に乗せる場合は「弾の大きさ / 射程 / 貫通」のどれにするかの決定が必要。
  - 風属性の貫通(WindPierce)は飛び道具に乗る。
- 魔法の前の魔法弾は2ヒットする(弾×1 + 着弾の爆発×1)。
  - 技の設計としては意図的に見える。
  - ただし平らなボーナス(攻撃力+)が1回で2倍効く。
  - 爆発の倍率を下げるか、爆発には平らなボーナスを乗せないかは、数値設計で決める。

### タイタン / 魔人(`QaSweep -qaBossKill`、カードなし・300秒まで)

- 新しい動きと、`-qaBkLegacyBoss 1`(以前の動き)を、同じボットで比べた。
- ボットは今回、「ボスの中心」ではなく「被弾範囲のプレイヤーに一番近い点」を狙うように直した。
  - 以前のボットは、タイタンの高い中心を狙って上攻撃ばかりになっていた。

**天空20km タイタン**(HP 1,100)

| キャラ | 以前の動き | 新しい動き |
|---|---|---|
| お嬢様騎士 | 0ダメージ | 57発、残り48%(あと約280秒の見込み) |
| 格闘 | 0ダメージ | 14発、残り65% |
| 忍者 | 0ダメージ | 94秒で撃破 |
| 竜人 | 0ダメージ | 129秒で撃破 |
| 黒剣士 | 143秒で撃破 | 68秒で撃破 |

**天空5km 魔人**(HP 1,380)

| キャラ | 以前の動き | 新しい動き |
|---|---|---|
| お嬢様騎士 | 206秒 | 223秒 |
| 格闘 | 149秒 | 226秒 |
| 忍者 | 30秒 | 33秒 |
| 竜人 | 61秒 | 47秒 |
| 黒剣士 | 57秒 | 36秒 |

- 魔人は、以前の動きでも近接キャラは倒せていた。
  - 調査の時の「10〜33分の見込み」は、主にボットの狙い方のせいだった。
  - 実際は、火球を跳ね返して当てていた。
- 新しい動きでは、直接殴れる時間が定期的に来る。
  - ただし、その間は火球が減るので、跳ね返しが主の格闘は遅くなった(1回ずつの比較で、ばらつきも大きい)。
  - `exposeEveryAttacks` / `exposeHoldTime` で調整できる。
- タイタンは、近接キャラでも攻撃できるようになった。
  - お嬢様騎士(1発10)と格闘は、カードなしでは300秒で倒し切れない。
  - `kneelEveryAttacks` / `kneelHoldSeconds` で隙を増やせる(数値の判断待ち)。
