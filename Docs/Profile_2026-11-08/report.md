# プロフィールの改善 2点(2026-11-08)

## 1. マップ別の記録を「どこまで走ったか」に
- 荒野街道・自然洞窟・天空回廊・LAST CORRIDOR のどれも、そのマップの自己ベスト距離を出す。
  - 100km を超えた記録も丸めない(例: 100,263 m)。
  - 「100km到達」「未到達」「到達」「クリア」の文字は出さない。
  - マップ名の横の「100km」は削除。左にマップ名、右に BEST 距離だけを並べる。
- 色:
  - 100km 以上は距離の数字だけ金色(HUD の MILE と同じ金)。
  - 100km 未満は白。
  - 記録が無いマップは灰色で「0 m」。
- 値の出どころ: 確定した記録だけを使う(成功のランで確定したマップ別 BEST と、1回のランの最高到達の大きい方)。
  - 失敗したランの距離は入らない。今までの記録の仕様と同じ。
- 一番上の「BEST」行は今までどおり常に金色(エステルの推奨: 全体の最高記録の印)。

## 2. 左のキャラ = 全体の BEST を出したキャラ
- 確定した成功のランで全体の BEST をはっきり超えた時だけ、「距離」と「キャラ ID」を一緒に保存する。
  - 保存キー: `ProfileBestCharV1`。中身は "キャラID|距離m"。SaveKeys に「進行」として登録。
  - 書く場所は RunLedger.CommitSuccess。落ちた確定を起動時にやり直す CommitJournal の復旧でも同じように書く。
- 動き:
  - 同じ距離なら前のキャラのまま。
  - キャラを選び直しても変わらない。
  - 記録対象外のラン(闘技場・練習・DEBUG)では書かない。
- 既存のセーブ:
  - 更新後の初回起動で、記録があるのに BEST のキャラが無ければ、その時選んでいるキャラを暫定として1回だけ書く(印 `|p`)。
  - その後は、BEST を更新した時に正しいキャラへ置き換わる。
  - 記録がまだ無いデータは何も書かず、選択中のキャラを出す。
- 壊れた値(知らないキャラ ID・数字でない距離)は読まずに、選択中のキャラを出す。エラーにはならない。
- カードの絵・名前・キャラ名の配置は変えていない。

## 試験(Windows、-memSave / -fileSave。本物のセーブには触れていない)
- 判定(logic): 失敗 0、例外 0。追加した L8 で確かめたこと:
  - 既存データには暫定のキャラが1回だけ書かれる。
  - キャラを選び直しても変わらない。
  - 竜騎士で BEST を更新すると、竜騎士と距離が一緒に保存される。
  - 同じ距離・短い距離のランでは変わらない。
  - 忍者が 100,263.4m の BEST を出すと、忍者に変わる。
  - 100km を超えた実際の値が出る。
  - 金色/白の境目が正しい。
  - 壊れた値は無視される。
  - 本物の確定処理を通している。ランキングには送らない印を付けている。
- 永続化(persist1/2、2回起動):
  - BEST のキャラ(竜騎士)とマップ別の距離が再起動後も残る。
  - 起動時に選択中のキャラ(弓使い)へ置き換わらない。
  - 失敗 0。
- 撮影(shots): 横・縦とも崩れなし、失敗 0、例外 0。
- ReleaseCompileCheck: 成功。

## エステルの確認
- 結論: 採用推奨。追加のレイアウト修正は不要。
  - マップ記録の一覧は読みやすい。
  - 金色は強すぎない。
  - 100km を達成したマップは金色で一目で分かる。
  - BEST のキャラが代表として自然に見える。
- BEST 行は常に金色のままを推奨。BEST の金は「全体の最高記録」、マップの金は「100km 達成」で、意味が違うため。
- 将来の案(今回は入れていない): 「100km 以上の記録は金色で表示」という短い案内。
