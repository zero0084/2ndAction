# マルチ 8人の負荷試験と通信量の削減(2026-10-12)

同じ Windows PC で HOST 1 + JOIN 7(127.0.0.1)。ボットが自動で走り、敵/ボスと戦う。JOIN2 は約 600m 先、JOIN3 は約 1,500m 先へ移動
(離れた人がいる時の同期範囲)。8プロセスが 1台の PC を分け合うので fps は実機より低い。試験スクリプト: scratchpad/mp/mp8.sh、比較: mp/cmp8.py。

## 1. 変更前(同期の版 3、コミット f123ba6)
4マップ × 8人(ボスあり 75秒)+ 荒野街道 60秒 + CO-OP 速度3倍 150秒(被弾/復活あり): 48プロセスで例外 0、全端末の撃破数一致、二重ダメージ 0。
HOST の送信 85〜121KB/s・約 900件/秒。うち位置の中継が約 77KB/s。

## 2. 対応(60274e7、同期の版 4)
| 対応 | 中身 |
|---|---|
| 位置を詰める | 1件 77B → 41B(色が白でない時 +4B)。時刻=ms、X/距離=mm、Y=cm、速度と姿勢=半精度 |
| 位置の中継をまとめる | HOST はその間に届いた全員の位置を、送り先ごとに 1件へまとめて毎秒30回だけ送る(以前は1人分ずつ別に送っていた) |
| 敵の状態を詰める | 1体 78B → 値のある欄だけ(雑魚で約 20B)。1件 13体まで |
| 近い人への回数を下げる(③) | **採用しない**。20回/秒で送信はさらに -12KB/s だが、相手の表示のずれが平均 0.97 → 1.50m と約5割増えた。開発版だけ -netSnapRate N で比べられる |
