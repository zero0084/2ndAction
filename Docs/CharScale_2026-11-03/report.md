# キャラの大きさと敵の見やすさ(2026-11-03、エステルと確認)

対象は現行版(ct422 と同じ中身 + 今回の変更)。確認は Windows の開発版(-qaMotion / -qaCharSelect / -qaBgTone)で、通常速度 30fps で撮りました。

## ① ラン中に体が伸び縮みして見える件

**調べ方**
- 14人それぞれで「走り → 地上3連撃 → 走り → 空中攻撃 → 着地 → 上攻撃 → 下攻撃 → 後ろ攻撃 → 被弾 → 復帰」を自動で動かしました(-qaMotion、H = 被弾を追加)。
- 実際に表示された絵を、出た順にゲームと同じ縮尺(PPU とピボット)で並べました(`seq_group1〜4.jpg`)。
- 頭・肩・胴体を目印に、走りの絵と比べました。エステルにも別に見てもらい、候補がほぼ一致しました。
- 大きさの差の原因は、どれも**素材ごとの PPU(表示の倍率)の合わせ漏れ**でした。描いた時の縮尺の差が、PPU でそろえきれていませんでした。
  - 表示の拡大(Transform)、カメラ、NPOT の引き伸ばしは関係ありませんでした。
  - 黒剣士以外の13人は、ほとんどの絵が同じ PPU です。その中の一部の動作だけが、描いた縮尺が違っていました。
- 倍率は、走りの絵の隣に候補を ×0.7〜1.3 で並べ、頭と肩が一番近い段を選びました(`scale_fix_1/2.jpg`)。

## ② キャラ選択の立ち絵

- 原因: 立ち絵は 1024×1536 の1枚絵を、そのまま表示枠いっぱいに出していました。そのため、槍先まで描いた竜騎士は人物が黒剣士の約0.8倍に見えていました。
- 頭の上〜足もとの高さを黒剣士にそろえるため、足もとを基準に次の倍率で拡大しました。
  - 竜騎士 ×1.12(エステルの意見で 1.15 → 1.12)
  - 弓兵 ×1.12(脚を大きく開いた構えのため、頭の大きさで判断)
  - 双剣士・竜人 ×1.08
  - 魔法使い ×1.05
- 忍者の低い構え、ルカとペンタの体格はそのままです。
- 切れて見える所について:
  - 元の絵で切れている所はありませんでした。
  - 枠からはみ出す所は、紙の縁の透かしを「見えている範囲」から測るようにしました(UIPaperFade の `_Vis`)。線・布・武器も内側で薄れるので、硬い切り口になりません。
- 切り替えの空白:
  - 以前は「消える 0.1秒 → 差し替え → 出る 0.1秒」で、枠が一瞬空になっていました。意図した演出ではなく、空白として不自然でした。
  - 前の絵を下に残す 0.1秒のクロスフェードに変えました。重なる時間が長いと二人が混ざって見える(エステル)ので、前の絵を早めに消します。
- 比較画像: `portrait_land_before_after.jpg`(横)、`portrait_port_before_after.jpg`(縦)。どちらも14人を同じ画面の大きさで並べ、上段が変更前、下段が変更後です。

## ③ 背景に敵が紛れる件

- 以前の背景調整(BackgroundTone)は今も全場面で効いていました。
  - 背景の絵だけに掛かるので、足場・穴・攻撃の予告・敵は変えません。
  - -qaBgTone で、全場面とも「調整なし」より敵が浮き上がっていました。
- 一番見づらかった場面: 荒野街道の夜(浮き上がり 1.70)・夕方(1.89)、ラスダン(1.97〜2.06)、荒野の夜明けの高速(2.04)。
- そこで荒野街道とラスダンだけ、背景の彩度と明暗差を少し強めに抑えました。結果は夜 1.96、夕方 1.94、ラスダン 2.09(通常速度と高速の両方で計測)。

## マスターの実機で見てほしい点
- 荒野街道の夜を高速で走った時に、暗い赤の敵を見つけられるか。エステルの意見は「背景をさらに弱めるより、敵の縁を明るくする方が効く」で、実機の結果を見てから決めます。
- キャラ選択の切り替え(0.1秒のクロスフェード)が、指で速く切り替えた時に気にならないか。

## キャラ選択のカード規格とカルーセル(APK 428)

**サイズ/枠がばらばらだった原因**
- 並びのカードは、1人ずつ別の1枚絵(`<id>_card.png`)を縦横比を保って出していた。絵の縦横比が 0.49(拳銃士 796×1984)〜0.60(ペンタ 972×1624)とばらばらで、それがそのままカードの外寸の差に見えていた。
- 枠・名前・役割・上の紋章は絵に焼き込まれていて、絵ごとに太さや色が違っていた(双剣士は暗い枠、ルカ/ペンタは名前の板が違う、など)。

**共通カード規格**(`CharacterSelectUI.Carousel.cs`)
- 外寸は全員 210×388(中央で ×1.10)。共通の枠を UI で組む:金の縁 → 紺の地 → 窓(立ち絵)→ 窓の細い金線 → 上と境目の菱形 → 名前の板(名前は金・太字、役割は淡い白。長い名前は自動で縮小)。
- 窓には大きい立ち絵(`<id>_main.png`、紙の地の1枚絵)から「体」の部分を出す。`BodyBox` 表(体の中心 x・頭の上・足もと)で、頭の上〜足もとが窓の高さの 86% になる範囲。
  - ルカ/ペンタは基準の高さを大きめにして、小柄さを残しつつ小さくしすぎない。忍者は低い構えのまま。
  - 竜騎士の槍・弓兵の弓は少し引いて入れた(エステルの意見)。竜人の翼は切れても迫力になるのでそのまま。
- 焼き込みのカードの絵は使わない。新しいキャラは立ち絵と `BodyBox` の1行で同じ規格になる。画像の修正はなし。

**カルーセル**
- 倍率は中央からの距離で連続して変わる(中央 1.00 / 隣 0.84 / さらに外 0.68。中央のカードは ×1.10 なので、絶対値は 1.10 / 0.92 / 0.75)。
  - 小さくなった分の隙間を詰める。中央は金の縁を明るく、背面に薄い光。隣は少しだけ暗く(0.8〜1.0)。
  - 中央から 3.2 枚より外のカードは描かない。
- 吸着の時間は 0.16〜0.30 秒(動く距離で決まる)、終わりがゆっくりの補間。**吸着が終わった時に選択を確定**する。大きい立ち絵の 0.16 秒のクロスフェード、名前・能力・キャラカードの更新もこの時。ドラッグ中は切り替わらない。
- 離した時の行き先:
  - 払いの速さが 500/秒を超えたら払った向きへ1人。2600/秒を超えたら2人まで。
  - 払っていない時は一番近いカード。ただしカードの間隔の 28% を超えて動かしていれば次へ。
  - Android で指を離したフレームの最後の移動も数える。
- 矢印・隣のカードのタップ・マウスホイール・キー(←/→、A/D)・パッド(十字/左スティック)は、どれも同じ吸着の動き。キー/パッドの左右はこの画面では PadNav のフォーカス移動に使わない(`PadNav.HorizontalOwnerFrame`)。
- タップの判定は、縮んだ見た目ではなく元の枠の大きさのまま。
- 未解放のキャラは今の仕様では一覧に出ないので、鍵の表示は対象外。
- 開いた時は保存してある選択キャラが中央。

**確認**(-qaCarousel、全項目合格)
- Windows(1920×1080 / 608×1080 縦)
  - 自動の項目: A 外寸同じ / B 部品同じ / H 倍率 / I 吸着の途中の倍率が連続(1フレームの変化 0.036 以下)/ J 0.23 秒で1回だけ確定 / C・D ドラッグと払い6通り / E 矢印 / K 隣のタップ / F キー / G パッド / O・P 立ち絵と名前 / S 再起動後も中央。
  - 本物の入力: OS のマウス操作とキー(←→←、D、A)を送って確認。59.5fps。
- Android エミュレーター(APK 428、host GPU): `adb input swipe/tap` の本物のタッチで確認。
  - 小さく動かす → 戻る / 1枚ぶんゆっくり → 次 / 軽い払い → 次 / 強い払い → 2人 / 逆向きの払い → 前 / 隣のタップ → 次。
  - 開いたまま 55fps、操作中 45fps。ソフトウェア描画では 2.6fps で、エミュレーターの描画の問題。
- 画像: `carousel_cards_before.jpg`(以前のカード)・`carousel_cards_14.jpg`(新しい規格で14人を中央に)・`carousel_land.jpg`・`carousel_port.jpg`・`carousel_portrait_14.jpg`、動画 `video/carousel_drag_flick_arrow_key.mp4`(コミットしない)。
