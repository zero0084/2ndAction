# 広告なしパスの購入をつなぐ(2026-11-19)

Play Console で `noads_pass` の登録・有効化が済み、ライセンスの公開鍵を受け取ったので、製品版の購入欄を本物の Google Play の決済につなぎました。
前回(2026-11-18)の内容は `Docs/Release_2026-11-18/README.md` を参照してください。

| 商品 ID | `noads_pass`(アプリの `MonetizationConfig.NoAdsProductId` と同じ) |
| 購入オプション ID | `standard`(購入・下位互換あり) |
| 種類 | 買い切り・非消費型として扱う |
| 状態 | 有効 |
| 価格 | JPY 300 / USD 1.89 / TWD 65.00 / KRW 2,800 / HKD 14.90(5か国・地域) |
| お支払いプロファイル | 設定済み・手数料 15% に登録済み |
| 銀行口座 | 追加済み。少額入金の確認は待ち |
| ライセンス テスター | **未確認** |

## アプリ側の確認・変更
### 使っている部品
- Unity IAP(`com.unity.purchasing`)5.4.4。中の Google Play Billing Library は 9.0.0。
- 価格: Unity IAP は `ProductDetails.getOneTimePurchaseOfferDetails()` から現地価格の表示(`getFormattedPrice`)を読みます。下位互換の購入オプションがある時は、その価格が返ります。
- 購入: 商品 ID だけで購入の画面を出します(一回限りの商品には offer token を付けない)。Play は下位互換の購入オプション `standard` で購入させます。
- 確定: 非消費型(NonConsumable)として登録しているので、`ConfirmPurchase` は Google への「承認(acknowledge)」になります。消費はしません。
  - 3 日以内に承認しないと Google が自動で返金するので、検証が通った時だけ承認します。

### 商品 ID と購入オプション ID
- アプリが使うのは商品 ID `noads_pass` だけです。購入オプション ID `standard` は、アプリの中では選びません。
- `standard` は記録のために `MonetizationConfig.NoAdsPurchaseOptionId` に書きました(判定には使いません)。
- **下位互換を外したり、購入オプションを増やしたりする時は、アプリの対応を見直す必要があります。** 今の Unity IAP は購入オプションを選べません。

### ライセンスの公開鍵
- `google_play_public_key.txt` を取り込みツール(`IapReceiptSetup`)で取り込みました。
  - 生成物: `Unity/2ndAction/Assets/Scripts/UnityPurchasing/generated/GooglePlayTangle.cs`(公開鍵を難読化した物。秘密の値ではないのでコミットします)
  - Android の定義に `OMM_IAP_TANGLE` が付き、製品版でも購入欄が出ます。
  - 鍵の指紋(SHA-256 の先頭 8 バイト): `034D4EE35CB2F703`。ファイルの鍵と、アプリの中に入った鍵の両方で一致を確かめました。
- ProjectSettings はコミットしない決まりなので、定義はこの PC の設定にだけあります。
  - そのため、製品版のビルド(`BuildAndroid.BuildRelease`)で、鍵のファイルがあれば定義を自動で足すようにしました。定義だけあって鍵のファイルが無い時はビルドを止めます。

### 今回直した所
1. 支払いは済んでいて、承認の前の注文(前の起動で承認まで行かなかった等)がある時、「購入を復元」で一瞬「購入の記録はありませんでした」と出ていました。
   - 今は、レシートを検証できて購入済みなら「持っている」と答えます(承認は今までどおり別の処理で行う)。
2. 起動時に商品の情報(価格)を取れなかった時、アプリを再起動するまで購入できませんでした。
   - 今は、復帰の時や「購入を復元」の時に、商品の情報を取り直します。
3. 価格を取った時の記録に、通貨と購入できるかどうかを足しました(logcat の `[IAP] products fetched`)。
4. 開発版の自己試験(`-qaIapValidate`)に、アプリに入った鍵が取り込んだ鍵と同じかの確認を足しました。
5. 「お知らせ」に版 458 を足しました(下)。
6. クレジットの CREATED BY を「Maziru Tabintyu」にしました(マスターの指定)。

### 前回までに対応済みで、今回コードを確かめた所
- 価格はストアから取った現地価格だけを表示します。取れない時は「価格を取得できません」で、押せません。検証の鍵が無い時は「購入の準備中です」で、押せません。
- 有効にするのは、レシートの検証(Google の署名・パッケージ名・商品 ID・購入済みの状態)が通った後だけです。
- キャンセル・支払いの失敗・支払い待ちでは有効にしません。支払い待ちの間は購入ボタンを押せず、「お支払いの完了待ちです」と出ます。
- 支払い待ちが完了した時は、アプリが動いていればその場で、閉じていれば次の起動で有効になります。取り消された時は、次の確認(復帰・起動・「購入を復元」)で待ちの印が外れ、また購入できます。
- 「もう持っている」と返った時は、ストアで確かめ直してから有効にします。
- 権利は端末に控えるので、再起動してもオフラインでも有効のままです。ストアが「持っていない」と 2 回続けて答えた時だけ外します(返金・取り消し)。

## ログイン特典(毎日 5,000 MILE)の確認
仕様は前回のまま変えていません(`Docs/Release_2026-11-18/README.md` の 2)。今回、最新のコードで次を確かめました。
- 対象: Windows 版、または広告なしパスを持っている人。両方に当てはまっても 1 日 5,000 MILE。MILE 2 倍は掛かりません。
- 日付の切り替え: 日本時間 0 時(世界共通。広告ガチャと同じ)。受け取らなかった日の分は繰り越しません。
- 購入した日・「購入を復元」で持っていると確かめた日も、その日の分がまだならその場で付きます。
- 所持 MILE と受け取った日は、同じ 1 回の保存で書きます。受け取った日は、進行のデータと設定のデータ(進行を初期化しても消えない)の両方に控えます。
- 既存のセーブとの互換: 新しいキーを足しただけで、セーブの形式(schema)は変えていません。古いセーブは「まだ受け取っていない」として読みます。
- パスの権利(設定の扱い)と、受け取った日・MILE(進行の扱い)は別のキーです。パスの権利はストアで確かめ直せるので、進行を初期化しても失いません。

## マスターの手順
### 1. AAB を作る(アップロード鍵。パスワードはマスターが入力)
Unity のエディタを閉じてから、PowerShell で実行します。
```
powershell -ExecutionPolicy Bypass -File Tools\ads\build_closedtest.ps1 -Keystore "<アップロード鍵の .jks>" -Alias <別名>
```
- 最後に表示される `_build.txt` で、次を確かめてください。
  - `versionCode=458`
  - `noAdsPass=purchase enabled`
  - `adsProfile=test`
  - `signing=upload key`
- 出力: `Unity\2ndAction\Builds\ClosedTest\OneMoreMile_ct458.aab`

### 2. クローズドテストへ上げる
- 既存のクローズドテストのトラックへ `OneMoreMile_ct458.aab` を上げます。
- 試す端末は、**Play から入れた版**を使ってください。adb で入れた APK では Play の課金を試せません。

### 3. 購入の前に: ライセンス テスターの確認(クローズドテスターとは別)
- Play Console の「設定 → ライセンス テスト」に、試験に使う Google アカウントが入っているかを確かめます。
  - クローズドテストのテスター登録とは別の設定です。クローズドテスターに入っているだけでは、本物の請求になります。
- 端末の Play ストアが、そのアカウントでログインしていることを確かめます。
- アプリで「内容と購入」→ 購入ボタンを押し、Google の購入画面に **「テスト用のカード、常に承認」などのテスト用の支払い方法が出る**ことを確かめます。
  - **出ない時(本物のカードしか出ない時)は、購入せずに閉じてください。** ライセンス テストの登録を見直します(登録してから反映まで時間がかかることがあります)。

### 4. 購入・復元の試験(上から順に)
| # | 操作 | 期待すること |
|---|---|---|
| 1 | 設定 → 広告なしパス → 内容と購入 | 購入ボタンに現地の価格(日本なら ¥300 の形)が出る。特典の 4 行目がログイン特典 |
| 2 | 購入 → Google の画面を閉じる | 「購入をキャンセルしました」。有効にならない。もう一度押せる |
| 3 | 購入 → 「テスト用のカード、常に拒否」 | 「購入できませんでした」。有効にならない。もう一度押せる |
| 4 | 購入 → 「テスト用のカード、数分後に拒否」 | 「お支払いの完了待ちです」。有効にならない。購入ボタンは押せない。数分後、アプリへ戻る(または「購入を復元」)と待ちが外れ、また押せる |
| 5 | 購入 → 「テスト用のカード、数分後に承認」 | 「お支払いの完了待ちです」。有効にならない。数分後に自動で「広告なしパスが有効になりました」。その日の分のログイン特典 5,000 MILE が付く(まだなら) |
| 6 | (5 の代わりに、または別の日に)「常に承認」で購入 | すぐに有効。その日の分の特典が付く |
| 7 | アプリを終了して起動し直す | 有効のまま。同じ日に特典は増えない |
| 8 | ホームへ入り直す・「購入を復元」を押す | 同じ日に特典は増えない |
| 9 | アプリを消して Play から入れ直す → 「購入を復元」 | 有効に戻る。入れ直すと端末の記録(進行・受け取った日)が消えるので、新しい進行に、その日の分の特典がもう一度付く(MILE は初期の額 + 5,000。前のデータの MILE が増えるわけではない。書き出したファイルを読み込んだ時は、そのファイルの受け取り記録に従う) |
| 10 | もう一度「購入」を押す | 購入済みの表示で押せない(または Google が「所有済み」と答え、確かめ直して有効のまま) |
| 11 | 翌日(日本時間 0 時の後)にホームへ入る | 5,000 MILE が 1 回だけ付く |

- 承認(acknowledge)の確認: 購入から 3 日以上たっても返金されていないこと(Play Console の注文管理で、テスト購入が「返金済み」になっていないこと)。
- テスト購入を最初からやり直す時は、Play Console の注文管理でテスト購入を返金・取り消します。アプリは次の確認で 2 回続けて「持っていない」と返った時に外します。
- うまくいかない時は、Android Studio の logcat で `[IAP]` と `[NoAds]` の行を見ると原因が分かります。

## Wi-Fi を必須にしない(2026-11-21、v459 から)
- v458 の公開の概要で「必須のハードウェア機能(`android.hardware.wifi`)の申告により配信が制限」と出た。
- 原因: LAN の部屋の自動発見のために `AndroidLanPermissions.cs` が足す権限(`ACCESS_WIFI_STATE` / `CHANGE_WIFI_MULTICAST_STATE`)から、Play が Wi-Fi を「必須」と推定していた(マニフェストに Wi-Fi の uses-feature は書かれていなかった)。
- 修正: 同じ所で `<uses-feature android:name="android.hardware.wifi" android:required="false" />` を明示。権限と LAN の機能はそのまま。
- 確認(開発版 APK 459 相当、エミュレーター):
  - aapt2: `uses-feature-not-required: name='android.hardware.wifi'`、推定(uses-implied-feature)の行が消えた。権限・ほかの機能の申告は v458 と同じ。
  - LAN の FIND GAME: 探し始めで MulticastLock を取り、戻ると放す(今までどおり)。
- 次の AAB: `Tools/ads/verify_closedtest.ps1`(ビルドの最後に自動で動く)が「Wi-Fi は必須ではない」を AAB と APK の両方で確かめる。v458 に当てると NG 2 件になる(確認済み)。
- v458 はそのままクローズドテストの審査へ(マスター判断)。
