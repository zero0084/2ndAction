# 広告なしパスの課金テスト準備・ログイン特典・クレジット(2026-11-18〜19)

マスターの依頼 3 件の作業記録です。試験の結果と、確認用ビルドの番号は下の「試験」「ビルド」にあります。

## 1. 広告なしパス(商品 ID `noads_pass`)

### 現行コードの確認(以前から実装済み)
- 商品: 非消費型 1 つ(`MonetizationConfig.NoAdsProductId = "noads_pass"`)。Unity IAP 5.4.4 / Google Play Billing。
- 価格: ストアから取った現地通貨の表示だけを使います(コードに価格は書いていません。取れない時は「価格を取得できません」で購入できません)。
- 購入の確認: レシートを検証してから確定(acknowledge)して有効にします。検証できない注文は確定しないので、Google 側で 3 日後に自動返金されます。
- 持っているかの判定: 端末には「最後にストアで確かめた控え」だけを置きます(設定の扱いで、データの初期化でも消えません)。
  - 起動時・復帰時・「購入を復元」のたびにストアで確かめます。
  - オフラインの時は控えのままです。「持っていない」が 2 回続いた時だけ外します(返金・取り消し)。
- 特典: 全画面広告の停止、MILE 2 倍(広告なし)、広告ガチャ相当(1 日 3 回、広告なし)。今回、4 つ目としてログイン特典を足しました。

### 今回直したところ
| 内容 | 以前 | 今回 |
|---|---|---|
| 支払い待ちのまま取り消された時 | 「完了待ち」の印が外れず、購入ボタンが押せないまま残った | ストアの確認で完了待ちの注文が無ければ、印を外す |
| 「もう持っている」の返事(購入の時) | 検証せずに有効にしていた | ストアで確かめ直し、検証できた時だけ有効にする |
| 前の支払いが完了待ちの時の購入 | 「失敗」扱い | 「完了待ち」扱い |
| 起動時にストアへ繋がらなかった時 | 再起動まで繋がらないまま | 「購入を復元」や復帰の確認で繋ぎ直す |
| レシートの検証 | 署名とパッケージ名だけ | 商品 ID が `noads_pass` であることと、購入の状態が「購入済み」(取り消し・完了待ちでない)も確かめる |
| 検証の部品の呼び方 | 古い形(警告) | Google Play 用の形 `CrossPlatformValidator(公開鍵, パッケージ名)` |

### 販売開始に必要なもの(検証の鍵)
- Play Console の「収益化のセットアップ → ライセンス」の公開鍵(Base64)が必要です。秘密の値ではありません。
- 取り込み方: 1 行のテキストファイルに保存して、Unity のメニュー `Tools/OneMoreMile/IAP: Import Google Play license key...` を選びます。
  - バッチでの実行: `Unity.exe -batchmode -quit -projectPath ... -executeMethod IapReceiptSetup.ImportFromArgs -licenseKeyFile <ファイル>`
  - これで `Assets/Scripts/UnityPurchasing/generated/GooglePlayTangle.cs` ができ、Android の定義に `OMM_IAP_TANGLE` が付きます。
  - 製品版でも購入欄が出て、購入を検証してから有効にするようになります。
- 使い捨ての試験用の鍵で、取り込みと 3 通りのコンパイル(Android の製品版・開発版、Windows の製品版)を通しました。試験用の鍵と生成物は消して、元に戻してあります。

テスト用のカードで試せるのは次のとおりです(ライセンス テストに登録したアカウントだけ)。
- 「常に承認」: 購入の成功。
- 「常に拒否」: 支払いの失敗。
- 「数分後に承認」「数分後に拒否」: 支払い待ち → 完了・取り消し。
- 支払いの画面を閉じる: キャンセル。

### 実際の課金試験の手順(マスターの端末)
1. 上の設定がそろった後、マスターからライセンスの公開鍵を受け取り、アイリーンが取り込みます。
2. 検証の鍵の入った AAB(アップロード鍵で署名)を、マスターが内部テストへアップロードし、端末に Play から入れます。
3. 使うアカウントがライセンス テストに入っていて、支払い方法に「テスト用のカード」が出ることを、購入の前に確かめます。
4. 次の順で試します。
   1. 購入の画面に価格(ストアの表示)が出る。
   2. キャンセル。
   3. 「常に拒否」で失敗。
   4. 「数分後に拒否」で、支払い待ちのあと取り消し。
   5. 「数分後に承認」で、支払い待ちのあと有効になる。
   6. アプリを消して入れ直し、「購入を復元」で戻る。
   7. 再起動しても有効のまま。
   8. 購入した日にログイン特典の 5,000 MILE が 1 回だけ付く。

## 2. ログイン特典(毎日 5,000 MILE)
- 対象: Windows 版、または広告なしパスを持っているプレイヤー。両方に当てはまっても 1 日 5,000 MILE です。
- いつ付くか: その日はじめてホームに入った時です。ホームにいる間に日付が変わった時も、その日の分を 1 回付けます。
  - 広告なしパスを購入した時と、「購入を復元」で持っていると確かめた時は、その場でその日の分を(まだなら)付けます。
- 日付の切り替え: 既存の広告ガチャと同じ `TrustedClock.DayKey` で、**日本時間 0 時(UTC 15:00)、世界共通**です。
  - モバイルは、通信できる時はサーバーの時刻(Google の接続確認の応答の Date)を使います。
  - Windows 版は端末の時計を使います(サーバーの時刻は取りません)。一度見た時刻より前へは戻さないので、時計を戻しても同じ日をもう一度受け取ることはできません。時計を先へ進める操作は、オフラインでは防げません(広告ガチャと同じ限界)。
- 額: 固定の 5,000 MILE です。MILE 2 倍は掛かりません。受け取らなかった日の分は繰り越しません。
- 保存: 所持 MILE と受け取った日を、同じ 1 回の保存で書きます。
  - 受け取った日は、進行のデータ(`LoginBonusV1`)と設定のデータ(`LoginBonusLastDayV1`)の両方に書きます。
  - 設定の方はデータの初期化でも残るので、同じ日に初期化しても 2 回目はありません。
- 案内: 「本日のログイン特典：5,000 MILE」を 3 秒表示し、コインの音を鳴らします。
  - 30 言語の訳は、エステルのレビューを経て反映しました(ID 11060 と 11061)。11061 の日本語はエステルの提案で直しました。
- 無料のモバイル版(パスなし)と iOS には付きません。
- コード: `Assets/Scripts/Monetization/DailyLoginBonus.cs`

## 3. クレジット
- 見出し・役職・説明・名前を英語で統一し、言語の設定によらず同じ表記にしました。対象は、設定の「制作クレジット」の画面とエンドロールの両方です。
  - 画面の見出しは「Credits」、案内は英語です。閉じるボタンなどの操作の文字は、今までどおり言語に合わせます。
- 名前の英字表記
  - Irene / Estelle / Alicia: 今までの英字表記と同じです。
  - MS Basic: MuseScore の音源の正式な表記です。
  - Pentatuttulu / Luka: ゲームの英語の名前(PENTATUTTULU / LUKA)と同じです。
  - **Majiru Tabibito(マジル旅人)は仮の表記です。** 正式な英字表記が見つからなかったので、マスターの確認が必要です。
- 「PLAYTESTERS」の欄を足しました。Nari、Moka、Soushi、Itsuki の順です。
  - 名前の一覧は `Assets/Resources/Credits/Playtesters.txt` です。1 行 1 名で、書いた順に出ます。`#` で始まる行は無視します。
  - 追加の時は、このファイルに行を足すだけで、設定の画面とエンドロールの両方に出ます。
- 文字の揃え: 題字・見出し・説明・名前・著作権の 5 種類で、それぞれ全項目の字の種類・大きさ・色・太さが同じです。すべて中央揃えで、間隔も固定です。
  - 長い名前は、字を小さくせずに枠の幅で折り返します。
  - 内容の高さは実際に並べた高さなので、最後の行(© 2026 MIXGame)まで送れます。
  - 同じ見出しが続く時(SPECIAL THANKS)は、見出しを 1 回だけ出します。
- エンドロールの不具合を直しました: 1 つの項目に英字の名前が複数ある時、全部が同じ位置に重なっていました(今までは複数の名前が日本語の銘板だけだったので、表に出ていませんでした)。今は道に沿って順に並びます。
