### ガチャ1回 / MILE 2倍(実装済み)

- 報酬は SDK の正規の報酬の通知のときだけ渡します。閉じただけ・失敗・在庫なしでは渡しません。
- 1回の表示で報酬は1回だけです。通知が重なった分は無視して数えます。
- 報酬の記録と MILE(またはカードと回数)は、同じ1回の保存で確定します。途中でアプリが落ちても、二重にも消失にもなりません。
- 報酬の通知が「閉じた」の後に届く SDK の順番に備えて、閉じた後 1.5秒待ちます(2026-10-14 追加)。
- 最後まで見なかった時の文言:
  - MILE 2倍:「最後まで見なかったため、追加の MILE は受け取れませんでした」
  - ガチャ:「…引けませんでした(回数は減っていません)」

## 4. 広告なしパス(`noads_pass`)

### 今の実装

- **出なくなる広告:** ゲームオーバー後の強制広告。
- **任意広告の扱い:**
  - MILE 2倍は、広告なしで受け取れます(1ラン1回、額は同じ)。
  - ガチャは、広告なしで1日3回引けます(広告で引く回数と同じ枠。購入しても今日の残りは戻らない)。
- **権利の確認:**
  - 起動時・アプリへの復帰時(60秒に1回まで)・「購入を復元」ボタンで確認します。ボタンは設定画面とパスの画面にあります。
  - ストアに繋がらない時は、最後に確認した状態のままにします。
  - ストアが「持っていない」と2回続けて返した時だけ外します(返金・取り消し)。
  - 端末の控えは設定と同じ扱いで、セーブの初期化・データの削除・引き継ぎでは消えません。再インストール・機種変更の後は「購入を復元」で戻します。
- **購入:**
  - レシートを端末内で検証してから確定(acknowledge)して有効にします。支払い待ちは有効にせず、完了したら自動で有効になります。
  - **検証の鍵(GooglePlayTangle)が無い間は、購入ボタンが「購入の準備中です」になり、買えません。**
- **未設定・未実装:**
  - 商品(Play Console の `noads_pass`)・価格・有効化は、**マスターの管理画面で確認が必要**です。
  - 検証は端末内だけです。サーバーでの検証や、返金のサーバー通知(RTDN)はありません。返金は起動時・復帰時の確認(オンラインの時)で外します。

### 決まっていない仕様(現状と推奨案)

| 項目 | 現状 | 推奨案 |
|---|---|---|
| 価格 | 未定(ストアの現地通貨表記をそのまま出す作り) | マスターの判断 |
| パスの特典の範囲 | 強制広告なし + 任意広告の報酬を広告なしで | このままを推奨(わかりやすく、報酬は増えないので釣り合いも崩れない) |
| クローズドテストでパスを売るか | 検証の鍵が無いので買えない | 初期版は「購入の準備中」のまま広告だけ試し、課金はライセンステスターで後から確かめる |

   - 同意メッセージ(GDPR・米国の州法)の公開
3. (課金も試す時)Play Console:
   - `noads_pass` の作成・価格・有効化
   - ライセンスキーをファイルで
   - ライセンステスター
4. (公開までに)開発者サイトのドメインと app-ads.txt。

### D. マスターの判断が必要な仕様
1. **署名の鍵**(アップロード鍵を作り Unity に設定する。以前の依頼で「署名鍵は今回は変更しない」となっていたので、変えてよいかの判断)。
2. クローズドテストのアプリ ID を本番(推奨)にするか、テスト用のままにするか。
3. クローズドテストで広告なしパスの購入まで試すか(商品の有効化はマスターの作業)。
4. 広告ユニットの設定(高エンゲージ OFF / ディスプレイのみ 等)と、強制広告の条件(起動5分・間隔5分・初回なし)を今のままにするか。
5. パスの価格。

### クローズドテスト初期版(全テスターにテスト広告)の最小手順(案)
1. マスター: アップロード鍵を用意し、Play Console でアプリとクローズドテストのトラック・テスターを作る(D1、C1)。
2. マスター(任意・推奨): AdMob でアプリを登録し、アプリ ID をアイリーンへ。
3. アイリーン: B1「テスト広告版の製品版」を作り、アプリ ID を入れて AAB を作る(Split あり、versionCode を上げる)。テスト広告であることは広告の中の「Test Ad」の表示で分かる。パスは「購入の準備中」のまま。
4. マスター: AAB をクローズドテストへ上げ、データセーフティ・広告あり・広告 ID の申告を済ませる(テスト版でも申告が必要)。
5. テスターの実機で、5章の「実機」の列を確認する(アイリーンが確認の手順書を用意)。
6. 本番広告への切り替えは、広告ユニット・同意メッセージ・app-ads.txt がそろってから、B1 の定義を外して行う。
