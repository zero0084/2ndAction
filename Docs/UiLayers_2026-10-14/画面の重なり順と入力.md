# 画面の重なり順と入力の修正 — 2026-10-14(APK 313)

実機で見つかった2件と、同じ仕組みの点検の結果です。位置の調整ではなく、描く順番と入力の受け付けを直しました。

## 1. カード選択の手前に天井の針の「!」が出ていた

### 原因
- 障害物の警告の「!」の札は IMGUI(`ObstacleWarning.OnGUI`)で描いていました。
- カード選択の画面は uGUI です。Unity では **IMGUI が uGUI より必ず手前**に描かれます。
- そのため、ゲームの時間が止まっている間も、「!」がカードの上に残っていました。

### 修正
- **「!」の札は撤去**しました(マスター指定)。描く処理ごと消しています。
- **赤い輪郭の警告は残します。** ただし、ラン中に画面を開いている間は出しません。閉じると、先読みの範囲にある障害物の輪郭がまた出ます。
- 「画面を開いている間」は、1つの共通の条件(`GameManager.RunScreenOpen`)にまとめました。含まれる物:
  - カード選択と、その開閉の演出
  - ポーズ
  - サブ画面
  - 設定・DEBUG・引き継ぎ・ランキング・お知らせ・広告などの共通の画面
  - 結果の画面
- 同じ条件で、ほかの「世界に付いた表示 / ラン中の帯」も、画面を開いている間は描かないようにしました。

  | 表示 | 以前 |
  |---|---|
  | YOU / CPU の名前の札 | 同じ条件を個別に持っていた → 共通の条件へ |
  | 落下の警告・脱出のゲージ(`PlayerController`) | 結果の画面だけ除外 |
  | コンボの数(`ComboCounterUI`) | 結果の画面だけ除外 |
  | COMBO 成立のお知らせ(`ComboSystem`) | 除外なし(閉じた後に出す) |
  | ボス戦の表示(`BossBattle`) | 結果の画面だけ除外 |
  | BONUS ZONE の帯・画面端の光 | サブ画面だけ除外 |
  | 解放のお知らせの帯 | **カード選択の上に重なっていた**(縦画面で1枚目の見出しを隠す。今回の確認中に見つけた)→ 選んだ後に出す |
  | 「脱出できます」の帯 | 同上。カード選択の間は表示の残り時間も止める |

## 2. CPU サポートの一覧の手前に「疾走出発(9地点)」が出て、「決定」に重なっていた

### 原因
- CPU サポートの一覧と、疾走出発のボタンは、どちらも IMGUI の同じ深さ(`GUI.depth = -950`)でした。
  - 同じ深さの間では、描く順番が決まりません。
  - そのため、疾走出発のボタンが一覧の手前に出ることがありました。
- 疾走出発のボタンの側は、「CPU サポートの一覧が開いているか」を見ていませんでした。
  - ボタンは描かれ、入力も受け付ける状態でした。
  - 逆向き(疾走出発の一覧を開いている時の CPU サポートのボタン)は、正しく止めていました。

### 修正
- CPU サポートの一覧を開いている間は、**疾走出発のボタンを描かない・押せない**ようにしました。
- 開いた一覧は、閉じているボタン(-950)より**必ず手前**の深さ(-960)で描きます。これは CPU サポートの一覧と疾走出発の一覧の両方です。
- 一覧は画面全体のタップを吸い取ります。閉じた時は、指が離れるまで背後へ通しません(以前からの仕組み `UiInputGate.LatchUntilRelease`)。
  - このため「決定」を押した指で、背後の疾走出発や uGUI の「出発」が反応することはありません。

## 3. 同じ仕組みの点検(IMGUI の深さが同じ組)
| 組 | 結果 |
|---|---|
| 疾走出発 ⇔ CPU サポート(-950 同士) | 上のとおり修正 |
| 闘技場の画面(-2000)⇔ 設定(-2000) | 闘技場のボタンが設定の手前に出るおそれ → 闘技場を -1990(設定より後ろ)へ |
| 広告なしパス(-2200)⇔ データ引き継ぎ(-2200) | 同時に開くことはまず無いが、同じ深さを避けて引き継ぎを -2250 へ |
| そのほか(設定 -2000 / DEBUG -2100 / ランキング -1900 / お知らせ -1850 / 初回の案内 -1800 / 練習の説明 -1500 など) | 深さが別々で、開いている間は背後の入力を止めている(`UiInputGate`)。変更なし |

- uGUI の画面(カード選択・デッキ編集・カード合成・キャラ選択・ステージ選択)の上に重なる IMGUI も点検しました。
  - ラン中の HUD の上の帯(BEST/距離/HP/レベル)は、もともとカード選択の上側に並べる設計です。
  - ポーズのボタン「II」と必殺技のボタンは、カード選択の間は出ません(以前から)。
  - 取得カードの一覧(RUN BUILD)は、カードの位置を避けます(以前から)。

## 4. 確認の結果

### Windows の開発版(専用の保存ファイル、`-qaLayers`、横 1280×720 / 縦 540×1170)
| 確認 | 横 | 縦 |
|---|---|---|
| ラン中(自然洞窟、CPU の仲間 2人):赤い輪郭が出ている所で「カード選択 → ポーズ → 設定」を開閉 × 5回。開いている間は輪郭・名前の札・解放のお知らせが出ない、閉じると戻る | 合格 | 合格 |
| マップ選択: CPU サポートの一覧の開閉 × 5回。開いている間は疾走出発のボタンを描かない・背後の入力を止める、閉じると戻る | 合格 | 合格 |

### Android エミュレーター(APK 314、専用の試験ファイル `qa_filesave.txt`)
| 確認 | 結果 |
|---|---|
| ラン中の画面の開閉(カード選択 / ポーズ / 設定)× 4回。**繰り返すたびに本当に画面を回転**(横 2400×1080 ⇔ 縦 1080×2400) | 合格(failures=0) |
| マップ選択の CPU サポートの一覧の開閉 × 4回(回転しながら) | 合格 |
| **adb で本当に押す**: 「CPU サポート」のボタン → 一覧の「決定」× 4回(横/縦を交互)。横画面では「決定」と背後の疾走出発のボタンが画面の上で**重なる位置**(重なり True) | 合格: 「決定」で一覧が閉じる。疾走出発の一覧は一度も開かず、出発もしない。閉じた後は疾走出発のボタンが戻る |

- 試験の作り直し(製品の不具合ではない物):
  - エミュレーターは処理が重く、0.3秒が 1〜2 フレームしかありません。そのため「直前のフレームに描いた」を拾って失敗していました → 時間と最低のフレーム数の両方を待つように直しました。
  - 待っている間に本物の LEVEL UP が来ると、カード選択が開いたままになります(縁が出ないのは正しい動き)→ 試験の側で選ぶようにしました。
