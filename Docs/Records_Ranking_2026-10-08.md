# 記録の確定・解放・ランキング ほか(修正依頼 2026-10-08)

前の依頼と矛盾する所は今回を優先した(特に「失敗したランも累計へ加算する」は撤回)。

## 1. 走行距離は成功したランだけ正式記録(Save/RunLedger.cs)

| 結果 | 扱い |
|---|---|
| 正規の帰還(ボス撃破後の脱出 / ラスダンの終わりの NO) | 確定: マップ別BEST・累計・解放・(資格があれば)ランキング |
| ゲームオーバー | 正式記録に入れない(結果画面に今回の距離は出し、「正式な記録には残りません」と書く)。お嬢様騎士の条件だけ見る |
| ホームの「破棄して NEW RUN」 | 何も記録しない(成功扱いにしない) |
| 中断(ポーズの RETURN TO HOME / アプリの一時停止・終了) | 未確定のまま中断データに保存 → CONTINUE 後の結果で決める |

- ラン中の数値(到達距離・実際に走った距離・使った機能)は RunLedger の「台帳」にだけ溜め、中断データにも入れる。
- 確定は一度だけ: 確定したランの ID を `CommittedRunsV1` に残す。保存の直後に落ちて同じランの中断データが残っても、再開させない。
- 失敗しても、過去に確定した記録は消さない。
- 累計は「成功したランの実走分」。疾走出発で飛ばした区間と、CONTINUE で戻って走り直した区間は足さない(何度やっても水増しされない)。ラスダンの距離は今までどおり累計に入れない。
- 対象外: 闘技場・練習・Debug Run、開発版のデバッグ機能(距離ワープ・無敵)を一度でも使ったラン(途中で OFF に戻しても、中断を挟んでも対象外のまま)。
- 疾走出発の行き先は「成功して確定したマップ別BEST」まで(55km なら 50km まで、60km は不可)。10km ごとの門番撃破の条件も今までどおり。
- マルチのランも、正規の帰還ならローカルの記録・解放には入る(ランキングには入れない)。

## 2. 解放は成功時に確定、未解放は隠す(Save/UnlockRules.cs)

- 条件は依頼の表のとおり(コードの表 StageRules / CharRules)。距離の条件はラン中は「仮判定」だけ: 条件を満たした時に名前を出さない控えめな知らせ「条件達成! 帰還すると確定します」。帰還で正式に解放する。
- お嬢様騎士: ラン用マップ(通常3マップ+ラスダン)で 1,000m 以下(ちょうども)の本当のゲームオーバー。闘技場/練習/Debug Run/リタイア/デバッグ使用は除外。
- 死神の遭遇は今までどおり戦闘開始の時にマップ別で保存(撃破不要)。ラスダン = 3マップすべてで遭遇 + 成功ランの累計 1,000,000m。出現演出「走り続けたあなたへ。最後の道が開かれました。」は1回だけ(表示済みを保存)。
- 一覧から完全に隠す: マップ選択(枠ごと出さない)、キャラ選択(解放済みだけを詰めて並べる。総数も出さない)、ホームの闘技場ボタン(解放まで出さない)、デッキ編集のキャラカード切り替え、ランキングのタブ、マルチの相手のキャラ名(自分が未解放なら名前を出さない)。新規データは荒野街道と黒剣士だけ。
- NEW: 解放したばかりの物は、ホームの扉/肖像画/闘技場ボタンに光る「NEW」、一覧の枠に「NEW」。一覧を開いた時点で「見た」になる(`UnlockSeenV1`)。複数同時でも全部に付く。お知らせも1件ずつ全部出る。

## 3. コードネーム(Save/Codename.cs)

- 設定の「プロフィール」で登録・変更。未設定でもソロは遊べる。ランキングへの初参加の時に確認する。保存だけでは投稿しない。
- 同じ名前を許す。本人の識別は UGS の PlayerId(マルチは接続番号)で、名前を変えても記録や本人は変わらない。
- 整え方: 前後の空白を除いて連続する空白を1つに、改行/タブ/制御文字/書式文字(向きの上書き等。絵文字のゼロ幅結合子は残す)/`<` `>`(装飾タグ)/`|` を除く。空白だけは未設定。
- **長さの上限: 16 文字**(見た目の文字数=書記素。絵文字の合成も1文字)。マルチでは 120 バイトまで(収まらない時は文字の途中で切らずに縮める)。
- マルチの待機室/頭上の名前/HUD/結果/復活ボタンに「P1 名前」で出す。LAN の部屋の既定名も端末名ではなくコードネーム(端末名に本名が入ることがあるため)。マルチの通信の版を 2 に上げた(古い版とは接続しない)。

## 4. オンラインランキング(Online/Leaderboard.cs, UgsLeaderboardBackend.cs, RankingPanel.cs)

- ソロのマップ別「最高到達距離」。各プレイヤー×各マップで自己ベスト1件。距離の降順、同じ距離は同じ順位(1, 2, 2, 4)。
- 一覧: 順位・コードネーム・距離・その記録のキャラ・オート/疾走の印(AUTO / SPRINT)。上位 50 と自分の順位・自己ベスト。タブは解放済みのマップだけ(闘技場は無し)。
- 状態の表示: 読み込み中 / まだ記録がありません / 読み込めませんでした+再試行 / 投稿待ち N+再送。
- 参加は任意: 最初に「コードネームと記録が公開される」案内 → コードネームの確認 → 参加。参加しなくても通常プレイと手元の記録はそのまま。参加をやめることもできる。
- 投稿の対象: 正規の帰還で確定した、この版以降のラン。除外: マルチ/闘技場/練習/Debug Run/テストデータ/デバッグ機能を使ったラン/旧データ(成功やデバッグ未使用を確かめられない)/開発版の「全部選べる」で選んだ未解放のマップ。オートと疾走出発は使ってよく、使ったかを記録に残す。
- 参加より前に確定した「資格のある自己ベスト」は、参加した時に送る。
- 投稿待ち: 送る前に保存し、通信失敗/オフラインは残して再送(ホームで30秒ごと/画面を開いた時/手動)。同じラン(runId)は二度送らない(端末でもサーバーでも)。短い記録で自己ベストを上書きしない。名前未設定・通信失敗でもローカルの保存は妨げない。

### 検査(端末の値をそのまま信じない)
サーバー側(Cloud Code `Tools/ugs/cloudcode/omm_submit_run.js`)が次を検査してから書く。端末からランキングへ直接書くことは Access Control(`Tools/ugs/access/omm_leaderboards.ac`)で禁止する。
- 形式: runId(32桁の16進)、マップ/キャラは既知の物だけ、距離は整数 1〜2,000,000m、プレイ時間 0〜48時間。
- 速さ: (距離 − 疾走の到着地点)≦ 160km/h × 1.2 × プレイ時間 + 300m。
- 疾走: 使った印と到着地点が一致し、到着地点がサーバーにある自己ベスト以下。
- 時刻: 開始 ≦ 確定 ≦ サーバーの今+10分、壁時計の経過 ≧ プレイ時間。
- 重複: そのプレイヤーの最近 200 件の runId(Cloud Save に保存)。
- 本人: Cloud Code の context.playerId(UGS の認証)で書く。表示名は整えてから metadata へ。
- 自己ベストより長い時だけ書く(更新の種類は "Keep latest" にして、判定はスクリプトが行う。名前の変更 `omm_set_name.js` で metadata を書き直すため)。

**検出できない範囲**: 改造した端末が「ありえる範囲の」値を作って送る不正(速さ・時間の上限の内側)、時計や速度の改ざん、自動操作ツール、複数アカウント。ゲームの中身の検証(ランの再現)はしていない。匿名アカウントはアプリの削除で別人になる。

### 確認の範囲
- **PC(Windows)で、模擬サーバー(同じ検査の規則をC#で実装、複数プレイヤーを別IDで再現)を使って確認した**: 自己ベスト更新/短い記録で上書きしない/同じ距離は同じ順位/別プレイヤー表示/オフライン→投稿待ち→再起動後も残る→再送1回/同じ runId の拒否/速すぎ・疾走の行き先・不明なキャラの拒否/名前の変更で本人と記録が同じ/デバッグ・テストデータ・旧データ・マルチ・闘技場の除外。
- **実際のオンラインサービスでは未確認**(プロジェクトが Unity Cloud に未連携)。Cloud Code の JavaScript も実行していない。

### Dashboard でマスターにお願いする作業(ONLINE PLAY の連携の後)
1. Unity Cloud Dashboard → Leaderboards → 4つ作る: `omm_best_wasteland_road` / `omm_best_natural_cave` / `omm_best_sky_corridor` / `omm_best_last_corridor`。並び順 = 降順(高い順)、更新の種類 = Keep latest score、リセット無し、バケット/ティア無し。
2. Cloud Code → Scripts → `omm_submit_run` と `omm_set_name` を作り、`Tools/ugs/cloudcode/` の内容を貼る(パラメータは各ファイル末尾の params と同じ)。
3. Access Control → `Tools/ugs/access/omm_leaderboards.ac` の内容(プレイヤーのランキングへの書き込みを禁止)を登録。
4. Cloud Save は設定不要(プレイヤーデータを Cloud Code が使う)。
- 料金がかかる可能性がある所: Leaderboards・Cloud Code・Cloud Save は無料枠を超えると従量課金(Cloud Code は実行回数と時間、Leaderboards/Cloud Save は呼び出し数と保存量)。確認場所は各サービスの Usage と組織の Billing。投稿は成功した帰還の時だけ、一覧は画面を開いた時と手動の更新(2秒あける、20秒は読み直さない)なので呼び出しは少ない。

## 5. オートモードの個別設定(HighSpeedAssist)

| 設定 | 内容 | 既存の設定 / 初期値 |
|---|---|---|
| オートモード ON/OFF | 全体 | 既存 `HighSpeedAssistEnabled` をそのまま |
| オート開始速度 | **既存の設定は距離ではなく走る速さ(km/h)** で、その値を維持(60〜160、既定 100) | 既存 `HighSpeedAssistEngageKmh` |
| ボス戦でもオート | OFF ならボス戦の間は自動の攻撃も回避もしない。撃破後は設定と速さに従って戻る。ラスダンの複数ボスも同じ | 新規 `AutoInBossV1` = ON |
| 自動攻撃 | 前の敵・壊せる障害物・ボスへの攻撃(下攻撃を含む)。OFF なら障害物を壊す前提の計画も立てず跳んで越える | 新規 `AutoAttackV1` = ON |
| 自動回避 | 穴・障害物・壁・トゲ・落下へのジャンプ/二段ジャンプ。ボス戦では弾・攻撃範囲・洞窟の危険も | 新規 `AutoAvoidV1` = ON |

- 新しい項目はどれも ON = 今までの動きと同じ。手動の操作が優先(今までどおり)。ポーズ/カード選択/ゲームオーバー中は自動入力を出さない(今までどおり)。
- 実際の範囲: **通常の敵の攻撃は回避の対象ではない**(敵は攻撃の対象だけ)。説明文にもそう書いた。必ず避けられるとは書いていない。

## 6. 長い説明文のスクロール

- uGUI(UI/UguiScrollText.cs): 報酬カードの説明、デッキ編集のカードの説明、キャラ選択の説明、マップ選択の特徴、確認ダイアログ。元の枠の中で横に折り返し、縦にスクロール(文字は縮めない)。文が変わったら(言語/表示対象)先頭へ。右に細いバー。
- IMGUI(UI/UiScroll.cs): 練習の説明、初回の案内、お知らせ、設定(説明を折り返して全体をスクロール)、ガチャの説明、疾走出発の説明と行き先の一覧、マルチのパネル全体、闘技場のキャラ説明、はい/いいえ の確認。
- ドラッグとタップを区別: 押してから 10〜14px 動いたらスクロール。その指は離してもボタン/カード選択/閉じるにならない。ガチャの「タップで閉じる」は、説明をドラッグした指では閉じない。
- スクロールにしなかった所: 結果画面(「タップでリトライ」が押した瞬間に反応するため、行の間隔を詰めて全部の行を収める。説明の行は折り返し)、COMBO の詳細(ラン中なので指のドラッグが操作と重なる。枠を画面の70%まで伸ばし、必要な時だけ文字を少し小さく)。
- 30言語: 新しい文を訳した。**既報の字形の崩れ(インド系/ビルマ/クメール/ラオの文字の組み立て)は Unity の旧テキストの限界で、スクロールでは直っていない**(読める量は増えたが、字形は崩れたまま)。
- ConfirmDialogUI の文が訳されていなかった(日本語のままだった)のを直した。

## 7. 障害物の破壊・被弾
- 攻撃での破壊は既存の演出(石=ひび→破片+砂ぼこり、木=木片、大型はカメラ揺れ。破片はプール上限72・寿命0.75秒、見た目だけ)を維持。
- 体当たりで消える石/壁/大岩は、黙って消えずに同じ破壊の演出で消えるようにした(当たり判定はすぐ外す。その端末だけの見た目)。
- 実際にダメージが入った時だけ「被弾」として数える(無敵/無敵時間/盾で無効な時は数えず、赤点滅/のけぞりも出ない — 既存の被弾処理は結果が Hit の時だけ反応する)。新しい後退/操作不能/ヒットストップは足していない。

## 8. 横画面の左右回転
- 横画面の設定では左右どちらの横持ちにも回る(`Screen.orientation = AutoRotation`、縦は無効)。縦画面を選んだ時だけ縦に固定(従来どおり)。
- 回った瞬間に触っていた指を捨てる(誤フリック/入力の残りを防ぐ)。ラン/入力内容はリセットしない。
- 安全領域: IMGUI は毎回 safeArea を読む(従来どおり)。uGUI のメニュー(キャラ/マップ選択・デッキ編集・合成・確認)は中身を左右の安全領域の内側へ寄せる(背景は画面いっぱい)。
- **Android 実機での回転は未確認**(PC では回転できない。画面の大きさ/安全領域の変化を見張る部分だけ確認)。

## 9. セーブ互換性と移行
- 所持品・正式な解放状態は消さない。既存データ(解放の仕組みより前)は今までどおり全部解放済みのまま、NEW は付けない。
- **成功/失敗の履歴は保存されていなかった**(ラン履歴のキーが無い)ため、旧記録を成功/失敗で分けられない。推測で削除・補正せず、マップ別BEST・累計距離・解放はそのまま残した。
- 旧記録はランキングの資格を持たない(この版以降に確定した成功だけ)。ローカルの旧記録はそのまま表示/疾走の範囲に使う。
- この版より前の中断データから CONTINUE したランは「旧データ」の印が付き、ローカルの確定はするがランキングには出さない。
- 新しい保存項目は SaveKeys に登録した(`CommittedRunsV1`, `UnlockSeenV1`, `Profile.CodenameV1`, `Ranking.*`, `AutoInBossV1`, `AutoAttackV1`, `AutoAvoidV1`)。

## 10. 自動テスト
- `-qaUnlock`(書き換え): 新規で見える物 / 同じ 30,000m で倒れたら記録・解放なし、帰還で確定 / 二度確定しない・確定済みの中断データは再開しない / 中断→CONTINUE で同じ台帳・デバッグの印を持ち越す / お嬢様騎士 / 疾走の範囲 / NEW と一覧 / ラスダン / 移行。
- `-qaRecords`(新規): コードネーム、ランキング(模擬サーバー)、オートの個別設定(実際のランで攻撃だけ/回避だけ)、無効な体当たり。
- 既存の `-qaSave` の累計距離の項目を新しい仕様に合わせた。
