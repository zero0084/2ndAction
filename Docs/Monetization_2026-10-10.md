# Android 広告 + 広告なしパス(買い切り)— 2026-10-10(依頼I)

Android 版は「無料 + 広告 + 買い切りの広告なしパス」、Steam/PC 版は広告も課金も無し。

**今回できているのは、模擬(開発版のみ)で全部の流れを動かすところまでです。**
- 本物の広告 SDK / 課金 SDK のパッケージはまだ入れていません。ダウンロードにはマスターの許可が要るためです。
- 本物とつなぐコード(AdMobAdService / UnityIapStoreService)は書いてあります。ただし `OMM_ADMOB` / `OMM_UNITY_IAP` の定義を付けるまでビルドに入らないので、**未接続・未確認**です。

## 2. SDK の選定と理由

- **広告: Google Mobile Ads Unity plugin(AdMob)v11.5.x**
  - Google 公式のプラグインです。同意(UMP: GDPR・米国の州法)が同梱されています。
  - テスト用の広告ユニット ID があります。インタースティシャルと報酬広告の両方に対応しています。
  - 報酬は `Show(reward => …)` の正規の通知だけで渡せます。
  - 旧 Unity Ads(com.unity.ads)は 2026-01-31 で収益化サポートが終わったため除外しました。
  - LevelPlay は代替案です。AGP 9 への対応が不明で、AdMob の需要を使うには結局 AdMob の設定も必要になります。
  - **既知の問題**: Unity 6000.5(Gradle 9.1 / AGP 9.0)で「Namespace 'com.google.unity.ads' is used in multiple modules」が出ます(plugin issue #4212、未解決)。回避策は gradle.properties に `android.uniquePackageNames=false` を入れることです。
- **課金: Unity IAP(com.unity.purchasing)5.4.x(Google Play Billing 9)**
  - v5 の API(StoreController / OnPurchasePending → 検証 → ConfirmPurchase)を使います。ConfirmPurchase が Google への acknowledge です。3日以内(ライセンステスターは3分)にしないと自動で返金されます。
  - 価格は `localizedPriceString`(ストアの現地通貨表記)をそのまま表示します。
  - 受け取ったレシートを端末内で検証します(CrossPlatformValidator、Google の公開鍵)。
- **SDK が保証しないこと**
  - **広告の長さとスキップは保証できません。** AdMob の「高エンゲージメント広告」(既定 ON)では、インタースティシャルが最長12秒、報酬広告が最長60秒でスキップ可能になります。OFF にすると 5秒 / 30秒です。設定は AdMob のユニット側です。
  - 動画/ディスプレイの種類もユニットの設定で選びます。短い広告を優先したい場合は「ディスプレイのみ」「高エンゲージ OFF」を推奨します。

## 3. 仕組み(コード)

**`Assets/Scripts/Monetization/`**

| ファイル | 役割 |
|---|---|
| `MonetizationServices.cs` | `IAdService` / `IStoreService` と、起動時のモード決定。None = Steam/PC/SDK なし。Store = 本物。Mock = 開発版のみ |
| `MonetizationConfig` | 間隔300秒・起動から300秒・1日3回・JST、商品 ID とユニット ID。**プラットフォームごとの値はここ。本番の値は未設定** |
| `AdManager.cs` | 表示の共通処理。主スレッドへの受け渡し、間隔、音の停止と復帰、入力の停止と離すまでの無視、報酬は1回の表示につき1回、復帰時にパスを確認 |
| `AdRewards.cs` | 報酬の記録(進行データ=テスト用データでは別)。MILE 2倍はラン ID ごとに1回、広告ガチャは日付と回数。抽選・カード・回数・記録を1回の保存で確定する |
| `TrustedClock.cs` | 日付の基準。HTTPS の Date ヘッダーでサーバーの時刻を取り、その後は端末の経過時間で進める。時計を戻しても「見た一番新しい時刻」より前にはしない |
| `NoAdsPass.cs` | 権利の控え(設定の扱い。初期化でも消えない)。オフラインは控えのまま。「持っていない」と2回続けて返った時だけ外す(返金) |
| `MonetizationUi.cs` | パスの画面。特典3つ・買い切り・制限・価格・購入・購入を復元・権利と育成データの復元は別 |
| `MockMonetization.cs` | 模擬(`#if UNITY_EDITOR \|\| DEVELOPMENT_BUILD`、製品版には存在しない)。本物と別のキー(Dev.)に保存する |
| `AdMobAdService.cs` / `UnityIapStoreService.cs` | 本物。定義を付けるまで入らない |

**`Assets/Scripts/` 直下と既存画面への組み込み**
- `GameManager.Monetization.cs`: 結果画面とホームの入口。
- 結果画面: 「広告を見て MILE 2倍」、パス所持時は「広告なしパス: MILE 2倍を受け取る」と、「通常○MILE＋追加○MILE＝合計○MILE」を表示します。
- ゲームオーバー後の結果画面をタップしてホームへ戻る時: 条件がそろえば強制広告を出してからホームへ戻ります。
- ホームのガチャ機のそば(縦画面は施設ボタンの上): 「広告で1回引く/本日あと○回/次の回復まで○」を表示します。
- 設定: 「広告なしパス」「購入の復元」「広告のプライバシー」(同意が必要な地域だけ)を並べます。
- DEBUG →「広告/課金(模擬)…」: 模擬の切り替え、振る舞い、日付を進める、回数を戻す、を操作できます。**本物の購入を呼ぶボタンはありません。**

**数え方と基準**
- MILE 2倍の額は「既存の計算が済んだ持ち帰り MILE」(`RunMile`)と同額です。カード倍率は掛け直しません。疾走のリングの MILE も含みます。
- 追加分は `AdRewardsV1.bonusMileTotal` に別に数えます。走行の記録・ランキングには入れません。
- 疾走の直後に短く脱出した場合の額(既存の疾走テスト I の実測。20km へ疾走し、全 Lv9 でリング3つ、到着直後に脱出):
  - 通常 300 MILE(リング 100×3、距離 MILE は疾走分を除くので 0)
  - 2倍で +300、合計 600
  - 全 Lv9 でない通常の疾走ではリングの MILE は 0 なので、通常分は「到着後に実際に走った距離 + 撃破」だけの小さな額です。追加もその同額です。
- バランスの数値は変えていません。

**今の時点の限界**
- **ラスダンの「NO」で終えた時**(結果画面が無い)は、MILE 2倍の申し出が出ません。
- **広告ガチャの回数**
  - サーバーが無いので、時計を**先へ進める**ことはオフラインでは防げません。時計を戻すこと・再起動・アプリの終了は防げます。
  - アプリのデータを消すと(再インストールなど)回数は戻ります。
  - 本格的に守るには、UGS Cloud Code(既存)に回数を持たせる必要があります。
- **返金**: サーバー通知(RTDN / Voided Purchases API)が無いので、起動時と復帰時の確認(オンライン時のみ)で外します。
- **マルチプレイ**
  - 強制広告は全員の勝負が決まった後(`NetMatch.RunOver`)だけ出します。観戦中・復活待ちは出しません。
  - MILE 2倍も勝負が決まった後だけです。

## 4. データの扱い(データセーフティの申告の材料)

**AdMob(Google Mobile Ads SDK)が集める物**
- IP アドレス(大まかな位置)
- アプリの操作(広告の表示/タップ)
- 診断(クラッシュ・性能)
- 端末の ID(広告 ID)
- `com.google.android.gms.permission.AD_ID` が自動で入るので、Play Console の「広告 ID」は「使用する」と申告します。

**申告の内容**
- 用途: 広告・マーケティング、分析、不正防止
- 第三者(Google)と共有: あり
- 暗号化して送信: はい
- 「アプリに広告を含む」: はい

**Unity IAP / Google Play Billing**
- 購入履歴(アプリの機能のため)。端末には権利の控え(購入トークンのハッシュ)だけを保存します。

**同意**
- 起動ごとに UMP で同意を確認します。広告を要求してよい時だけ SDK を初期化します。
- 「プライバシーの設定」ボタンは設定画面にあります(必要な地域だけ表示)。
- 対象年齢を 13歳以上にする前提で、子ども向け(TFCD)は付けていません。13歳未満を対象にする場合は設定の追加が必要です。

## 5. マスターにお願いする登録・設定・ID(本番の接続に必要。アイリーンは行いません)

**AdMob**
1. アカウントと支払い情報を作る。
2. アプリを登録する → **アプリ ID**(`ca-app-pub-…~…`)
3. 広告ユニットを2つ作る → **インタースティシャルのユニット ID**、**報酬広告のユニット ID**
   - 推奨: 高エンゲージ OFF。可能ならディスプレイのみ。
   - 報酬は「1 / MILE」程度の名目でよい(ゲーム側は額を使いません)。
4. 頻度上限(任意。ゲーム側でも5分間隔)。
5. app-ads.txt(開発者サイトに置く)。
6. プライバシーと同意メッセージ(GDPR・米国の州法)を作って公開する。
7. テスト端末の登録(実機確認の時)。

**Google Play Console**
1. 支払いプロファイル(販売者アカウント)。
2. アプリ内アイテム → 1回限りの商品(非消費型)
   - **商品 ID** を決める(作成後は変更不可。仮の名前は `noads_pass`)
   - **価格**を決める
   - 有効化する
3. **ライセンスキー**(収益化の設定 → Base64 の公開鍵)。Unity IAP の Receipt Validation Obfuscator で `GooglePlayTangle` を作る時に使います。
4. ライセンステスター(テスト購入用のアカウント)。
5. 内部テストトラックへ AAB をアップロードする(課金のテストには Play 経由のインストールが必要)。
6. アプリのコンテンツ
   - 広告あり / 広告 ID / データセーフティ(上の4.) / プライバシーポリシーの URL
   - コンテンツのレーティング(ガチャ要素あり)
   - 対象年齢

**Unity 側(許可をいただければアイリーンが行います)**
1. Google Mobile Ads Unity plugin と Unity IAP 5.x をパッケージとして入れる(ダウンロードあり)。
2. Android の Scripting Define Symbols に `OMM_ADMOB;OMM_UNITY_IAP` を付ける(Standalone/Steam には付けない)。
3. `Assets > Google Mobile Ads > Settings` にアプリ ID を入れる。
4. gradle.properties に `android.uniquePackageNames=false` を入れる(AGP 9 の既知の問題の回避)。
5. `MonetizationConfig` に本番のユニット ID と商品 ID を入れる。
   - 開発版は常にテスト広告です。本番のユニット ID は製品版でだけ使います。
6. GooglePlayTangle を作る(ライセンスキーが必要)。
7. 確認: SDK のテスト広告 → ライセンステスターでのテスト購入 → 実機。

**本番の契約、商品の有効化、ストアへの公開は行っていません。**
