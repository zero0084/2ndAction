# v1.0 最終容量監査(2026-10-25)

方針: 必要なゲーム内容は削らず、完成版に残っている無駄だけを取り除く。

## まとめ

- **Windows 版の 3.87GB の原因は、画像の約9割が無圧縮(1画素 4バイト)で入っていたことでした。**
  - Windows の GPU 圧縮(DXT / BC7)は 4x4 のブロック単位なので、幅か高さが4の倍数でない画像は圧縮できず、無圧縮に落ちていました。
  - 以前の Android(ETC2)と同じ原因です。Android は ASTC にした時に解決済みで、Windows だけ残っていました。
- 直し方:
  - 画像を4の倍数にそろえました。1,255枚、透明な画素を1〜3画素足すだけです。絵の位置は変わりません。
  - Windows の形式を BC7 にしました。
  - 絵・アニメ・解像度は1枚も削っていません。

| | 前 | 後 | 差 |
|---|---|---|---|
| Windows 製品版のフォルダ | 3,871,115,006 バイト | **1,475,666,926 バイト** | **−62%** |
| Windows を圧縮した大きさ(deflate) | 1,181,309,177 | **632,438,978** | −46% |
| Windows を圧縮した大きさ(LZMA、Steam に近い) | 1,015,810,092 | **590,175,976** | −42% |
| Windows の画像メモリ(ホーム) | 1,638MB | **750MB** | −54% |
| Windows の作業セットの山(ラスダン) | 3,809MB | **1,507MB** | −60% |
| Android APK | 413,164,938(371) | 413,142,366(372) | −22,572(ほぼ同じ) |

- **ストアの準備で必須の点が1つ見つかりました(Android)。** AAB を分けないと、Google Play の上限を超えます。
  - 今の作りでは、AAB の base モジュールが約396MB あり、Google Play の上限 200MB を超えています。
  - **Split Application Binary** を ON にすると、base は約168MB になります。残りは install-time asset pack(インストールと同時に届く)へ分かれます。
  - ストア用の AAB を作る方法(`BuildAndroid.BuildStoreAab`、分ける設定入り)を用意しました。
- 大きな問題はほかに見つかりませんでした。
  - Android は前回(10/18)の最適化が効いたままでした。
  - 音・フォント・開発用の素材にも、大きな無駄はありませんでした。

## 2. 画像

### Windows の圧縮(前)

| 形式 | 枚数 | 大きさ |
|---|---|---|
| 無圧縮 RGBA32(4の倍数でないため。DXT5 / BC7 を指定していても無圧縮) | 1,389 | 3,312MB |
| 無圧縮 RGB24(不透明で4の倍数でない) | 20 | 93MB |
| DXT5 / DXT1(4の倍数の物だけ) | 492 | 309MB |

### やったこと

1. **4の倍数へそろえた**: `Tools/art/pad4.py`。対象は 1,255枚です。
   - 対象の条件: Sprite、Clamp、透明がある物。背景・つながる絵・繰り返しの絵・不透明な絵は除きました。
   - 足すのは透明な画素だけです。足し方:
     - 横: 左右に分けて足す。
     - 縦: 下端・独自のピボットの絵は上だけ、中央のピボットの絵は上下に分ける。
   - **独自のピボット(702枚)は、同じ画素を指すように数値を直しました。** ずれは最大 0.000001画素です。
   - 下端/中央のピボット(553枚)は、Unity が比率で決めるため、横に奇数だけ足した時だけ 0.5画素ずれます。テクスチャの 0.5画素は画面では約 0.1〜0.25画素で、見えません。
   - 検算: 全 1,255枚で次を確かめました。
     - 足した後の絵の中の元の部分が、元の画像と画素まで同じ。
     - 幅・高さが4の倍数になっている。
   - PNG の色の情報(gAMA / sRGB など、206枚にある)は元のまま残しました。
   - 記録: `4の倍数へそろえた画像.tsv`(元/後の大きさ・足した画素・ピボットの前後)
2. **Windows の形式を BC7 にした**: `TextureImportRules` に Windows の決まりを足しました。
   - 4の倍数の画像だけ BC7(1画素 1バイト)です。4の倍数でない画像には指定しません(指定すると RGBA32 に落ちるため)。
   - Max Size は Android と同じにしました。
   - 起動ロゴの絵(Brand)は除きました。
3. 4の倍数でないまま残した画像(Windows で無圧縮のまま): 154枚・215MB
   - 背景・地面・天井の帯・つながる絵: 透明を足すと、並べた時にすき間が出るため。
   - 繰り返し(Repeat)の絵。
   - 開いた時に大きさが縮む物。
   - 一覧は `Builds/SizeGuard_*.txt` の windows-raw に出ます(下の 20章)。

## 3. 重複・未使用・開発用

- **同じ絵**: ビルドの中に、画素まで同じ画像が48組ありました(余分 Android 17.5MB / Windows 前 110MB → 後 約27MB)。
  - ほとんどがわざと同じ絵を使っている所です(break と breakloop、行って戻るコマ、敵の1枚絵と走りの1コマ目など)。
  - ボスの move は、すでに再生順の仕組み(move_seq.txt)があります。それ以外は、コマを1つにまとめると技の絵の選び方のコードを変えることになります。
  - v1.0 直前なので見送りました。一覧: `ビルド内の同じ絵.tsv`
- **未使用**: `Resources` の下の各フォルダは、全部コードから読まれていました。
  - BossAnim は、決まった名前の姿勢のコマだけを読みます。余分な古い絵はありませんでした。
  - `Resources/EnemyTierTest`(DEBUG 用の比較データ3件・数KB)はシーンから参照されています。小さいので残しました。
  - 自動の削除はしていません。
- **開発用**:
  - 製品版の C# に、開発用の型(QaSweep / EndgameDebug / NetAutoTest / CardBalanceTest / DebugPointer / LastDungeonQa)は入っていません。
  - ReleaseCompileCheck(開発の定義なしのコンパイル)が通りました。62個のアセンブリです。
  - 開発用の画像・試験用の素材はビルドに見つかりませんでした。
  - 「Placeholder」というフォルダ名の音は、本番の音です。

## 4. 音・フォント

- 音: 418個・18.8MB。
  - BGM はストリーミング + Vorbis(品質 0.55〜0.7)、SE は ADPCM・モノラル・読み込み時に展開。

## 5. 起動時の読み込み / 実行中のメモリ

### 起動時に常駐する物

- シーンが参照する画像(Windows で 前 651MB → 後 320MB)は、起動した時に読み込まれます。
- キャラの絵は、キャラの一覧(`Resources/Characters`)から参照されています。**12人全員分が起動時に読み込まれる作りのまま**です。
  - ホームの画像メモリ: Windows 750MB / Android 467MB
- ボスのコマ(BossAnim)は、ボスが初めて出た時に読み込みます。**今までは一度読むと、ホームへ戻っても残り続けていました**(static の控え)。
  - **直した(低リスク)**: シーンを読み直す時(ランの終わり → ホーム)に控えを手放し、使っていない素材を片付けるようにしました。
  - ランの途中は今までどおりです(同じボスが出ても読み直さない)。
  - 測った結果(大コウモリ・バジリスク・三姉妹を出した後のホーム):
    - Windows: 片付けない時 865MB → 片付けた時 821MB
    - Android: 499MB(片付けた時)
    - ラスダンのボスラッシュ(9体以上)の後は、もっと大きく効きます。
- 見送り(v1.0 の後の候補): 選んでいない11人のキャラ・別のステージの背景・ラスダン/エンドロールの絵を、必要な時だけ読む作り。
  - 効果は Android で数百MB の見込みです。
  - ただし、キャラの一覧の参照を名前で読む作りへ変える大きな変更になり、出発やカード表示のつくりを広く変えます。リスクが高いので残しました。

## 10. 今後の容量のルール

`容量のルール.md` にまとめました。自動の見張りは2つあります。

- `TextureImportRules`: 新しく置いた画像に、Android(ASTC)と Windows(BC7)の設定を自動で掛けます。
- `SizeGuard`(新規): ビルドのたびに自動で動きます。止めはしません。
  - 4の倍数でない画像(Windows で無圧縮になる)/ 上書きの無い画像 / 4096 を超える画像を `Builds/SizeGuard_<機種>.txt` に出します。
  - 出力の大きさを `Builds/SizeHistory.tsv` に記録します。前回より 5% 以上増えたら警告します。
