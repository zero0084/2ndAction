## 1. CONTINUE 後の空中撃破・BREAK の二重加算(修正済み、8cfb1744)
- 原因: 中断の保存には「中断した時点」のラン中の数(BREAK の回数など)が入るが、再開は「チェックポイント(直前のボス報酬)」から走り直す。
  - 走り直す区間で同じ BREAK/空中撃破がもう一度起き、ラン中の数と累計の両方に2回入っていた。
- 直し方(確率の判定などは入れていない。数え方だけ):
  - 再開した時、ラン中の数(BREAK/空中撃破)をチェックポイントの時点へ1回だけ戻す。
  - 累計(空中撃破/BREAK)は「このランで何回目まで足したか」を覚えて(保存キー ChallengeRunMarkV1、SaveKeys に登録)、走り直しの区間では足さない。それを超えた新しい分だけ足す。
  - 達成済みのチャレンジは今までどおり印があるので、通知も MILE も出直さない。
- 試験(Windows、-memSave / -fileSave。本物のセーブには触れていない):
  - 中断→CONTINUE を3回くり返す、チェックポイントを挟む/挟まない、累計の目標の直前(49→50 / 99→100)、新しいラン、壊れた保存値。失敗 0、例外 0。
  - 2回起動(1回目で数えて終了 → 2回目で CONTINUE): 再起動を挟んでも同じ。失敗 0、例外 0。
  - これまでのプロフィール/チャレンジの試験(L1〜L8)・永続化(2回起動)・再開の準備画面の試験(A/B/C/R/O): すべて合格、例外 0。
  - 製品版のコンパイル確認(ReleaseCompileCheck): 成功。

## 2. 定型メッセージの2台確認(af0669cb)
- 直したこと(定型メッセージの範囲の中だけ。自由入力などは足していない):
  - HOST は、送った本人へ文を返さない。以前は返していて、本人側で「自分の番号なら出さない」と消していた。番号が決まる前だと、本人の画面に2回出る可能性があった。
  - HOST 側の連投の見張りを「4秒に5通まで」に変えた。以前は「前の文から 0.8 秒」で、通信の遅れで2通がまとめて届くと正しい文を捨て、送った本人の画面にだけ出ることがあり得た。
  - 送る側のボタンの連打止め(1秒に1回)は今までどおり。
- 試験: Windows で2つ起動する自動の確認(-netAutoChat)。
  - 部屋で両方向に送る → JOIN が退出して入り直す → また両方向 → 同じフレームで2回押す → 改造した端末の連投を再現(8通) → ラン中に両方向。
  - 両方の記録を突き合わせて調べた。
