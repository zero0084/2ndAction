# 終了・中断の入口 / 画面設定 報告(2026-10-31 夜)

## 1. 終了・中断の入口

| 端末 | 入口(タイトル・ホーム) | 一時停止 | 押した時 |
|---|---|---|---|
| PC(Windows) | 「ゲーム終了」(タイトルは右下、ホームは右上の列の一番下)/ Esc・マウスの戻る・パッドの B(一番上の階層で) | 「ゲーム終了」 | 確認 →「ゲーム終了」で中断の保存をしてからウィンドウを閉じる |
| Android | 「端末のホームへ」/ 端末の戻る(一番上の階層で) | 「中断して端末のホームへ」 | 確認 → 中断の保存をしてから端末のホームへ(アプリは閉じない: moveTaskToBack) |
| iPhone / iPad | 置かない(押しても閉じないため) | 「中断を保存」 | 中断を保存して、成功した時だけ「中断を保存しました。ホームの『続きから』で {0}m から再開できます。」。マルチ/記録しないモードでは「保存できません」と出す(閉じない) |

- ゲームの中の「ホームへ戻る(RETURN TO HOME)」と、端末の「ホーム画面」は文言で分けた(「端末のホームへ」「中断して端末のホームへ」)
- ホームの「ゲーム終了」のアイコンは**エステルと相談して新しく描いた**「出口」の絵(石のアーチ・半開きの扉・白金の光・金の矢印。家の形は使わない = ゲームの中のホームと混ざらない)。`Resources/UI/Icons/home_exit.png`

### 確認の窓
- 見出し: 「ゲームを終了しますか？」(PC)/「端末のホームへ戻りますか？」(Android)
- 本文(ラン中):
  - ソロ: 既存の「ホームへ戻る」と同じ約束 = 「ランは終了せず、直前のチェックポイント({0}m)からCONTINUEできます。それより後に獲得したMILE・EXP・カードは取り消されます。」
  - 闘技場・操作の練習など記録しないモード: 「このランは続きから再開できません」
  - マルチのホスト: 「ルームを解散して退出します。ほかの参加者のプレイも終わります。このランは途中から再開できません。」/ 参加者: 「ルームから退出します。このランには途中から戻れません。」
  - Android: 「アプリを閉じずに端末のホームへ移動します。」(バックグラウンドに残ることは保証しない言い方。エステルの指摘)
- **初めに選ばれているのは「キャンセル」**(毎回。前回の選択は覚えない)。Esc / マウスの戻る / パッドの B / 端末の戻る でキャンセル(1段だけ閉じる)
- 開いた入力では確定しない: 開いた時に押しているキー/指は離すまで無効 + 開いてから 0.35秒は「ゲーム終了」を受け付けない(Enter の押しっぱなしで開いて確定まで進まない)
- タイトルの「何か押すと開始」とは競合しない: 確認が開いている間・閉じた指が離れるまで・右下の終了ボタンの上・Alt を押している間(Alt+Enter / Alt+F4)はタイトルを始めない

### 戻る操作の流れ
- サブ画面(設定・デッキ編集・合成・キャラ選択・ステージ選択・ランキング など): Esc / 戻る で一番手前を1段だけ閉じる(今までどおり)
- ラン中の Esc: 一時停止を開く(今までどおり)
- **タイトル・ホームの一番上の階層での Esc / 戻る / パッドの B: 終了の確認**(iOS は何もしない)

### 保存とゲームの結果
- 終了・端末のホームへの前に、既存の中断の保存(`SaveInterruptState` → RunCheckpoint)と進行の記録を書く(`GameManager.SaveForExit`)
- **中断・終了は脱出の成功として扱わない**(持ち帰り MILE・距離の記録・報酬は確定しない。既存のルールのまま)
- ウィンドウの × / Alt+F4 / OS からの終了も `Application.wantsToQuit` で同じ保存を通る(確認は出さない)。確定していない表示の設定はここで元に戻す
- スマホのホーム操作・アプリの切り替えは、既存の `OnApplicationPause` の中断の保存(そのまま)。アプリの終了の時だけに頼っていない
- カードの選択中・報酬の表示中: 再開はチェックポイントの状態から(順番待ちのレベルアップは保存、開いていた選択は捨てて出し直す = 既存の作り)。下の試験で重複・消失が無いことを確認
- マルチ: 今の退出の仕組みに合わせた(PC の終了はアプリの終了の時にオンラインの部屋を退出、LAN はプロセスが閉じれば切れる。Android はその場で `NetSession.Leave` してゲームのホームへ戻してから端末のホームへ)。マルチのランは中断の保存をしない(既存)

## 2. 画面設定(PC)

設定の画面(タイトル・ホームの「設定」、一時停止の「設定」から)の「画面」:
| 項目 | 内容 |
|---|---|
| 表示モード | ウィンドウ / 枠なし全画面 / 全画面(排他)。**排他の全画面は使っているグラフィックスで本当に排他になる時だけ出す**(このゲームの Windows は DirectX 12 で、Unity では排他を指定しても枠なしになるため、今の製品では「ウィンドウ / 枠なし全画面」の2つ) |
| 画面サイズ | 1280×720 / 1600×900 / 1920×1080 / 2560×1440 / 3840×2160 と画面が対応する大きさのうち、モニターに収まる物 |
| 適用 → 確認 | 「この設定を維持しますか？」(あと{0}秒で元の設定に戻ります)。**15秒以内に「維持する」を押さないと元に戻す**。実時間で数えるので一時停止中も進む |
| ウィンドウの端のドラッグ | 大きさを変えられる(Player 設定 resizableWindow を ON)。止まって 0.6秒で保存。最小は 640×360(縦長は 360×640) |
| Alt+Enter | ウィンドウ ⇔ 枠なし全画面(自前の処理。Unity の標準の切り替えは止めた)。**その Enter は決定に使わない**(キーの割り当ての読み取りで Alt を押している間の Enter を無視) |
| 全画面 → ウィンドウ | 直前のウィンドウの大きさへ戻す(保存してある) |
| 保存と復元 | 確定した表示モード・画面サイズ・最後のウィンドウの大きさを保存し、次の起動で戻す |
| モニターの変化 | 起動時と2秒ごとに、ウィンドウがモニターより大きければモニターの 95% に収める |

## 3. サイズ・向き・文字の大きさ
- 小さいウィンドウ・縦長・横長: 縦長のウィンドウでは既存の縦画面の並び(デッキ編集の配置 V2 など)に切り替わる。設定の画面は今までどおりスクロールで最後まで操作できる。確認の窓は画面に収まるよう文字を縮める
- **文字・UIの大きさ: 標準 / 大きめ**(設定の「表示」。全端末)。設定・お知らせ・案内・確認の窓・結果・ガチャ・タイトルの案内など、文字を読む画面の倍率を 1.15 倍に。短い辺がおよそ 690px 未満の画面では効かない(大きくすると収まらないため。見切れないことを優先)。ラン中の HUD は既存の「HUDの大きさ」、カードの画面(uGUI)は画面の大きさで並べ直す作りなので対象外
- スマホの画面の向き: 「自動 / 縦固定 / 横固定」の並びと言葉に(以前は 横画面 / 縦画面 / 自動)
- 端末ごとに出す項目: 画面(表示モード・画面サイズ・垂直同期・FPS)は PC だけ、画面の向き・縦画面のラン表示はスマホだけ、キー設定は PC だけ(既存の PlatformCaps)
- キー設定の説明に Tab / マウスの戻るボタン / Alt+Enter / Esc を追加(前回の残り)
