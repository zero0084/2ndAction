# 起動ロゴ: Unity のロゴを消す / MIXGame の起動ロゴ(2026-10-24)

## 1. Unity のロゴの非表示(済み)

**設定**
- Project Settings → Player → Splash Image の **Show Splash Screen を OFF**、**Show Unity Logo も OFF** にしました。
  - `ProjectSettings.asset` の `m_ShowUnitySplashScreen: 0` と `m_ShowUnitySplashLogo: 0` です。
- Player の共通の設定なので、Windows / Android / 将来の iOS のすべてに効きます。
- Unity のロゴの絵(約2.7MB)もビルドに入らなくなりました。APK は 365 → 366 で 100,801 バイト小さくなっています。

**ライセンス**
- Unity の公式サポートの記事によると、Unity 6 から Personal でも起動ロゴを消す/変えることができます。
  - Unity 6 より前のバージョンでは、Personal では消せませんでした。
- このプロジェクトは Unity 6000.5.6f1 で、ライセンスは Unity Personal です(ビルドのログで確認)。有料プランへの変更は要りません。
- 出典: https://support.unity.com/hc/en-us/articles/212165803 / https://docs.unity3d.com/ScriptReference/PlayerSettings.SplashScreen-show.html

**確かめた方法**
- 起動の記録 `[Boot]` を足しました。Unity のロゴが出たかどうか(`SplashScreen.isFinished`)と、最初の画面までの時間をログに出します。製品版も同じです。
- Windows の製品版: シーンの読み込みの前の時点で `unitySplashFinished=True`(ロゴは出ていない)。
- Android(エミュレーター、APK 366): `unitySplash(show)=False`(ロゴは出ていない)。
- 比べるために作った試験版(Unity の起動ロゴの仕組みで自前のロゴだけを出す版)では `show=True` になりました。判定が正しく働いていることも確かめています。

**黒い画面について(気になる点)**
- Unity のロゴを消したので、ゲームの最初の画面が出るまでの間は何も描かれない画面になります。
  - Windows: 黒。起動から最初の画面まで、この PC で 約3〜5秒。
  - Android: OS の起動画面(濃い灰色)。
- 以前は、この時間の一部を Unity のロゴの演出が埋めていました。
- ちらつき(白い画面が一瞬出るなど)は、ログと Android の撮影では見つかっていません。
- 黒い時間を MIXGame のロゴで埋めるかどうかが、下の「実装方法」の選びどころです。

## 2. MIXGame の起動ロゴの実装方法(用意済み、ロゴの確定待ち)

2つの方法を用意して、実際に測りました。

| | 方法A: Unity の起動ロゴの仕組みに MIXGame のロゴだけを入れる | 方法B: ゲーム側で描く(BootSplash、作成済み) |
|---|---|---|
| 出る時期 | 起動してすぐ(この PC で約0.7秒)。読み込みと同時に進む | ゲームの最初の画面が出てから(約3〜5秒の黒い画面の後) |
| 黒い画面 | ロゴと背景色で埋まる | 埋まらない(今と同じ) |
| 起動時間 | ほぼ増えない(読み込みと重なる) | ホームまで 約1.6〜1.8秒増える(飛ばせば 約0.5秒) |
| 長さ | Unity の決まりで、ロゴ1つ2秒以上 + フェード | 自由(今は 0.4秒で出る / 0.7秒表示 / 0.4秒で消える / 背景 0.25秒) |
| 飛ばす | できない(読み込み中なので、飛ばしてもホームは早くならない) | タップ/クリック/キーで飛ばせる(ホームの準備ができるまでは待つ) |
| 動き | Unity の用意した寄り(Dolly)か静止だけ | 軽い寄り・フェードなど自由 |
| 対応 | Windows / Android / iOS で同じ設定 | 同じ(IMGUI で描く。横・縦で大きさを合わせる) |

**おすすめ(アイリーン)**
- 依頼の条件(1〜2秒、飛ばせる、読み込みは省略しない)を全部満たすのは **方法B** です。
- 「黒い画面を出さない」「起動時間を増やさない」を優先するなら **方法A** です。
- 正式なロゴが決まったら、両方を実機で見比べて、マスターに選んでいただくのがよいと思います。
- どちらも、正式な絵を1つ置くだけで切り替えられます。

**方法B(作成済み)の中身**
- ファイルは `Scripts/UI/BootSplash.cs` です。
- 正式なロゴの絵 `Resources/Brand/MIXGame_Logo` が無い間は、何もしません。今は絵を置いていないので、ゲームは今までどおりすぐホームへ進みます。仮の素材は入れていません。
- 起動して最初の1回だけ出ます(ラン → ホームでは出ません)。自動試験の時も出しません。
- 表示中はホームの操作を止めます。飛ばした指はホームのボタンへ通しません。
- 起動直後の重いフレームでフェードインが飛ばないように、演出の時計は1フレームで最大 1/30秒しか進めません。
- ロゴの大きさは、横画面は横幅の46%・高さの42%以内、縦画面は横幅の80%・高さの30%以内です。

**試した結果(開発版、試しの絵はプロジェクトの外に置いて起動引数で読ませた)**

| 場面 | 結果 |
|---|---|
| 横画面 | 1.75秒で終わる |
| 縦画面 | 1.76秒で終わる |
| 読み込み中(0.07秒)に飛ばす | ホームの準備まで待ってから 0.52秒で閉じる |
| 準備後(0.6秒)に飛ばす | 0.99秒で閉じる |

- 本物の指やマウスでの確認ではなく、開発版の「この時刻に押した」扱いの入口で確かめました。
- `candidates_board.jpg` の下の段が、C案をこの方法で表示した様子です。

## 5. 正式採用: C案 + 方法A(2026-10-25)

マスターの決定: C案(三毛猫のシンボル + 虹色の MIXGame)、方法A(Unity の起動画面の仕組み、Unity のロゴは出さない)。

### 正式素材

- 置き場所: `Brand/MIXGame/`(一覧と作り方は `Brand/MIXGame/README.md`)
- 背景が透明な PNG:
  - 全体: 猫 + MIXGame + 「by マジル旅人」
  - 作者名なし
  - 猫だけ(大・小)
  - 文字だけ
  - 「by マジル旅人」だけ
- 表記は C案の絵の文字そのまま(「MIXGame」で正しい)。フォントで組み直す必要はありませんでした。
- 三毛の柄と星の目はそのままです。
- 起動画面用の絵: `Unity/2ndAction/Assets/Art/Brand/` の2枚
  - 横 1920x1080: ロゴは高さの5割
  - 縦 1080x1920: ロゴは高さの3割
  - どちらも背景は C案の背景と同じ #060810 で、中央にロゴ(「by マジル旅人」入り)

### 方法Aの組み込み方

- ロゴは Unity の起動画面の **背景の絵** として登録しました。ロゴの欄(logos)には入れていません。
  - ロゴの欄に入れると、ロゴを出し終わってからシーンの読み込みが始まります。
    - ロゴの後に約2.2秒の無地の画面が残りました。
    - ホームまでの時間も約1.5秒延びました(最初の画面が約4秒)。
  - 背景の絵にすると、ロゴと読み込みが同時に進みます(最初の画面が約2.5秒)。
- 背景の絵のぼかし(Unity の既定では ON)は切りました。
- 設定は `Assets/Editor/BrandSplashSetup.cs` が行います(メニュー Tools/2ndAction/Apply Brand Splash)。
- 起動直後の「読み込み中…」の板は、起動の時だけ出さないようにしました(`LoadingScreen` の静かな覆い)。
  - 代わりに、ロゴと同じ #060810 の無地で覆います。
  - ロゴ → 無地 → ホームの順につながり、板が一瞬出る不自然さがなくなります。

### 確認の結果

**Windows 製品版**(本物の保存と別の名前の試験用の製品版で確認。下の「保存の保護」を参照)

| 項目 | 結果(2回) |
|---|---|
| ロゴ | 起動してすぐ、画面の中央に出る(`windows_landscape_logo.jpg`) |
| ロゴの長さ | 約2秒、その後フェード |
| ロゴの後の無地(#060810) | 約0.7〜0.8秒 |
| ホーム | フェードで出る |
| 最初の画面 | 2.50秒 / 2.61秒 |
| 「読み込み中…」の板 | 出ない |

- 流れの一覧: `methodA/windows_sequence_2runs.jpg`(約0.15秒ごと、上下が2回分)
- 気になった点: ロゴの間、画面の中央にマウスの「待ち」のカーソル(青い輪)が出ます。Windows が起動中のアプリに出すものです。

**Android(エミュレーター、APK 370、横・縦)**

| 項目 | 横画面 | 縦画面 |
|---|---|---|
| 起動画面 | 有効(`unitySplash(show)=True`) | 有効 |
| ロゴの絵 | **エミュレーターには写らない**(下を参照) | 同じ |
| 起動からホームまでの画面 | #060810 の無地 → ホーム | 同じ |
| 黒・白・灰色のちらつき | なし | なし |
| ホームの向きと配置 | 正しい | 縦の配置で正しい |
| 最初の画面 | 22.5秒 | 24.5秒 |

- 最初の画面の時間は、エミュレーターが実機の約10倍遅いためです。
- 流れの一覧: `methodA/android_landscape_sequence.jpg` / `methodA/android_portrait_sequence.jpg`
- **Android でロゴが写らない件(実機での確認をお願いします)**
  - エミュレーターでは、起動画面の間ずっと背景の色だけが写り、ロゴの絵が一度も写りませんでした。
  - 次のどれでも同じでした:
    - 描画方式: GLES3 / Vulkan
    - 絵の形式: ASTC / 圧縮なし
    - 試しにロゴの欄にも絵を入れた診断用の版
  - つまり、Unity の起動画面の絵そのものがエミュレーターに写っていません。
  - 絵がビルドに入っていること(APK が約0.65MB 増えた)と、起動画面が有効なこと(ログ)は確かめています。
  - エミュレーターの画面の取り込みの制限の可能性が高いと考えています。ただし、実機で出るかはアイリーン側では確かめられませんでした。
  - 実機でロゴが出ない場合は、Android だけ方法B(ゲーム側で描く、作成済み)に切り替えるのがよいと思います。ホームまで約1.5秒延びます。
- 縦向きの端末で起動すると、縦用の絵が選ばれます(ログで `NativeWindow 1080x2400` を確認)。
  - 縦向きで起動して、ゲームの設定が「横」の場合は、起動画面は縦で出て、ホームで横に回ります。これは今までと同じ動きです。

### 保存の保護(今回の確認のやり方)

- Windows: 製品版と同じ中身を、製品名だけ「One More Mile Test」にして作りました(`Assets/Editor/BuildWindowsProductSandbox.cs`)。
  - 保存の場所(レジストリ・フォルダ)が本物と分かれるので、本物の保存には触れません。
  - 製品名はビルドの後に必ず元へ戻ります。
  - 毎回、試験の前後で本物の保存(レジストリ)を書き出して比べました。1バイトも変わっていません。
- Android: 起動のたびに専用の試験ファイル(`-fileSave bs/save.json`、縦用は `bs/port.json`)を使いました。
  - ログで「normal save untouched」を確認しています。
- 既存の保存を書き換える試験は行っていません。
