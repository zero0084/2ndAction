# アプリ容量の調査と最適化(2026-10-18)

## 結論
- **「3.3GB」はアプリの大きさではありません。** Unity のビルドが作ったファイルを、全部足した数字です。
  - 中身は、APK の材料(Gradle 用の素材)・IL2CPP が作る C++ のソース・ネイティブのライブラリ・APK そのものです。
  - 途中のファイルと完成品を二重に数えています。
- APK が大きい本当の原因は、**画像の大半が無圧縮で入っていた**ことです。
  - Android の既定の圧縮(ETC2)は、幅と高さが4の倍数の画像しか圧縮できません。
  - 今の絵の多くは 1237×1272 や 1672×941 のような大きさです。そのため 883枚(1.41GB)が、**1画素 4バイトの無圧縮**のままでした。
- **Android だけ ASTC で圧縮する決まり**(`TextureImportRules`)を入れました。絵・大きさ・位置・ピボットは一切変えていません。
  - APK: **606.8MB → 335.5MB(−45%)**
  - 画像メモリ: **1,427MB → 438MB(−69%)**
  - インストール後: **734MB → 449MB(−39%)**
- 今回追加した12キャラのアニメーションは、**1枚も削っていません**(498MB → 138MB)。

## 5. 実施した最適化
1. **`Assets/Editor/TextureImportRules.cs`**: Android の画像の圧縮を、用途ごとに ASTC にしました。
   - 対象は `Assets/Art` と `Assets/Resources` に置いた画像で、新しく置いた画像にも自動で掛かります。
   - キャラ・敵・ボス・UI・カード: ASTC 4x4(1画素 1バイト)
   - 背景・地面・飾り: ASTC 5x5(0.64バイト)
   - エフェクト: ASTC 6x6(0.44バイト。今の専用の取り込みと同じ)
   - 専用の取り込みがある所は、そのままです。BossAnim・闘技場・MechDragon・攻撃の絵・命中の衝撃・景色(すでに ASTC 6x6)が該当します。
   - **Android の設定だけ**を変えました。Windows 版、絵、大きさ(Max Size)、PPU、ピボット、メッシュは変えていません。
   - 1,498枚の `.meta` で、Android の欄が「上書き・ASTC」になりました。
2. **カードの種類のアイコン**(`Resources/CardCategoryIcons` 7枚)は、Android だけ上限を 256px にしました。
   - 元は 1254px ですが、カードの上では最大でも約80px で表示しています(一番大きいカード 幅380 × 0.135 × 拡大1.15 × 高解像度の端末)。
   - 1枚 6.3MB → 0.07MB になりました。
3. 確認用の道具を追加しました。
   - `SizeAudit.Run`: Build Report を TSV にします。
   - `SizeAudit.AstcCompare`: 圧縮の画質を比べます。
   - `BuildAndroid.BuildProbe`: 番号を進めずに比較用の APK/AAB を作ります。
   - `QaSweep -qaMemProbe`: 起動時間・画像メモリ・同じ場面の撮影をします。

## 6. 最適化の前後(同じ条件で作った比較用の APK、エミュレーター android-35 x86_64)

| 項目 | 前 | 後 |
|---|---|---|
| APK | 634.7MB(中身 606.4MB)* | 335.5MB |
| AAB | 570.5MB | 322.0MB |
| インストール後 | 734MB | 449MB |
| 画像メモリ(Unity の計測、ホーム) | 1,427MB(1,241枚) | 438MB(1,241枚) |
| 画像メモリ(ラン中、5キャラ) | 1,432〜1,433MB | 443〜444MB |
| GPU ドライバのメモリ(Unity の計測) | 1,444〜1,448MB | 455〜459MB |
| 起動 → 画面が出るまで(am start の TotalTime) | 3.3秒 | 3.6秒* |
| 起動 → ホームで計測を始めるまで | 44.2秒 | 32.9秒* |
| 例外・エラー | 0 | 0 |

*「後」は AAB の作成と同時に測ったため、CPU の取り合いがあります。それでもホームまでは約11秒早くなりました(読み込む画像のデータが 1/3 になったため)。エミュレーターは ARM の命令を変換して動かすので、実機よりずっと遅いです。比べる目安として見てください。もう一度だけ測り直そうとしましたが、エミュレーターの画面が止まったため取れていません。

*比較用の APK は、Gradle が前の APK の上へ書き足したため、中身の外に 28MB の隙間がありました。中身(606.4MB)は APK 324 と同じです。次の作成からは、前の出力を消してから作ります。

- **このゲームは、ほぼ全部の画像を起動時に読み込みます**(ホームの時点で 1,241枚)。
  - そのため、画像の容量がそのまま実行中のメモリになっていました。
  - 今回の圧縮で、メモリも約1GB減ります。
- エミュレーターのプロセスのメモリ(PSS)は、どちらも 760〜810MB でした。
  - エミュレーターでは描画を PC 側が受け持つため、画像は PSS に出ません。
  - 実機では PSS の「Graphics」に出ます(実機での確認をお願いしたい所です)。
- **FPS**:
  - エミュレーターはソフトウェアで描くため、測れません。
  - Windows 版は設定を変えていないので同じです。
  - ASTC は GPU が読むデータが 1/4 になるので、実機では同じか軽くなるはずです。**実機での確認が必要**です。

## 7. 画質
- `images/画質比較_元の絵とASTC.png`: 元の絵を ASTC で圧縮して戻した物と、元の絵を、1:1(拡大なし)で並べた物です。
  - 黒剣士・お嬢様騎士・巫女・竜人・竜騎士・ボス・カード枠・背景・エフェクトを並べています。
  - 細かい模様(お嬢様のマントの星、巫女の金の飾り、竜人の鱗)も、見て分かる違いはありません。
  - 元との差(PSNR、不透明な部分): キャラ ASTC 4x4 で 33〜39dB、背景 5x5 で 40dB、エフェクト 6x6 で 39dB。
- 実際の表示は元の絵の 1/4〜1/5 に縮めるので、違いはさらに見えなくなります。
- エミュレーターで、各キャラへ寄った画面も撮りました(`emu_base` / `emu_opt`)。ブロック状の崩れや色ずれはありませんでした。
- 参考に 6x6 も試しました。2倍に拡大すると細部が少し甘くなるため、キャラには使っていません。

## 10. Android の確認
- 確認したのは、**エミュレーター**(android-35 x86_64、ASTC 対応の GLES 3.1)だけです。
- **実機ではまだ確認していません**。マスターの実機での確認をお願いします。特に見てほしい所は次のとおりです。
  - 画質(キャラ・背景・UI)
  - FPS・発熱
  - 起動時間
  - `dumpsys meminfo` の Graphics
- ASTC を使えない古い端末(GLES 3.0 までの Mali-4xx や Adreno 3xx など)では、Unity が読み込み時に展開します。表示は正しいですが、メモリは前と同じになります。

## 11. 確認(Windows の開発版)

- Android(エミュレーター)の `-qaMemProbe` は、前・後とも失敗 0、例外 0 でした。
