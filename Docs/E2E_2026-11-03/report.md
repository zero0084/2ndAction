# 初回プレイ〜帰還の確認(ct422 基準、2026-11-03)

## 使ったビルドと環境
| 用途 | ビルド | 環境 |
|---|---|---|
| 通常の出発・雑魚の出現(手で操作) | ct422 の APK(versionCode 422 / 2026-11-03 0821、アップロード鍵) | Android エミュレーター(API 35, x86_64)、データ消去後の新しい保存 |
| 自動確認(直す前の再現・直した後) | 製品版と同じ中身 + 確認用の入口だけ(OMM_RELEASE_PROBE)の Windows 版。製品名は「One More Mile Test」で、本物の保存とは別 | Windows 11。毎回、確認用の保存と控えを消してから。本物の保存は前後で同一 |
| 自動確認(直した後) | 同じ中身の Android APK(`BuildAndroid.BuildReleaseProbeApk`、デバッグ鍵、配らない、versionCode は変えない) | 同じエミュレーター、`pm clear` の後 |

自動確認 `ReleaseRunProbe` は起動を3回に分ける: ①出発 → 1,000m まで → ボス → 報酬 → BONUS → 被弾 → ホームへ戻る → CONTINUE → 被弾 → 裏へ回して強制終了(Android は端末のホームボタン → force-stop)
②再起動 → CONTINUE → 脱出 → 結果  ③再起動 → MILE と記録が残っているか。
移動の間は HP を満タンに保ち、自動操作補助を 0km/h から効かせる(無敵の設定はランの記録を付けなくするので使わない)。BONUS ZONE は「ボスの後の抽選」の当たり/外れだけを当たりに固定し、条件の判定は本物のまま。

## 結果
| 確認 | 結果 |
|---|---|
| 1. 通常の出発で 1,000m までに雑魚 | 合格。ct422 では 61m で最初のゴブリン。自動確認では 15m から、1,000m までに 48〜57 体 |
| 1. BONUS ZONE の敵(ボスの後の抽選に当たった場面) | 合格。10 体(Windows / Android) |
| 2. 中断と CONTINUE の HP・最大HP・カード | **不具合を2件再現 → 修正 → 合格**(下記) |
| 3. 1,000m のボス → 脱出 | 合格。結果は脱出成功 |
| 3. 持ち帰り MILE | 合格。表示額(Windows 100 / Android 86)が1回だけ所持に入り、ホームへ戻っても増えず、再起動後も残る。中断データも残らない |

### 不具合① CONTINUE で HP が戻る(報告の「HP+20」)
- 再現: 1,000m のボスの報酬で HP 60/60 → 2発受けて 40/60 で中断 → CONTINUE で **60/60(+20)**
- 原因: 2026-10-15 から、中断の保存はチェックポイント(ランの始め・ボス報酬の後)の状態を書き換えない。再開ではチェックポイントの時点の HP に戻っていて、その後に受けたダメージが消えていた(コードのコメントは「中断の時点の HP」のままだった)
- 修正: 中断の保存に「中断の時点の HP」を足し、再開ではその値を使う(上限はチェックポイントの最大HP)。距離・カード・EXP・MILE は、画面の説明どおりチェックポイントへ戻る
- 確認: 中断 50/70 → 再開 50/70。強制終了の前 40 → 再起動して再開 40(Windows・Android の両方)

### 不具合② 中断中にキャラカードを付け替えると、再開後の最大HP・能力が変わる
- 再現: 中断中にホームで HEART UP をキャラカードに付ける → 再開で最大HP 60 → **70**。外すと 70 → **60**
- 原因: 再開時に、その時点のキャラカードの枠を読み直していた
- 修正: チェックポイントにランの出発時のキャラカードを記録し、再開ではその組を使う(メモリ上だけ。保存の枠は変えない)
- 確認: 付けても外しても、最大HP・能力はチェックポイントのまま

## マスターの Android 実機で見てほしい点
- ラン中に被弾してから一時停止 → ホームへ戻る(またはアプリを閉じる)→ 続きから。HP が中断した時と同じか
- 脱出成功の結果画面の MILE と、ホームの MILE の増え方(広告で2倍にした場合も含めて)

## 補足
- 1,000m のボスへのダメージは、攻撃の命中と同じ入口へ小分けに当てた(手での戦闘ではない)
- 直す前の動きは `-probeLegacy` で再現できる(Windows で確認: 失敗2件ずつ)
- 開発版の試験 `-qaRewards` の期待値も「中断の時点の HP」へ合わせた
