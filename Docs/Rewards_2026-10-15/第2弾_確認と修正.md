## 1. 人数分配の数値(72・36・23・17 → 72・36・24・18 に修正)
### 原因
- 端数を、獲得の経路ごと(雑魚 / ボス / BONUS / リング)の別の入れ物に貯めていました。
- 距離の MILE は、毎回切り捨てていました。
- 帰還の時、経路ごとに残った 1 未満の端数が別々に捨てられていました。
- 例: 3人の時
  - 距離 26.488 ÷ 3 = 8.829 → 8(0.829 を捨てる)
  - ボス 46 ÷ 3 = 15.333 → 15(0.333 は入れ物に残ったまま捨てる)
  - 合計 23
- 人数での分配が二重に掛かっていたのではありません(各経路で1回だけ)。

### 修正
- 端数の入れ物を1つにしました(全経路の端数を貯める)。
- 距離の MILE を整数にする時に、残りの端数も足します。
- 持ち帰り = floor(全経路の正確な合計)。1 未満の切り捨ては、帰還(とラスダンの YES の受け取り)の1回だけです。
- 中断データには、端数(1つ)を保存します。以前の形(経路ごと)は、読み込む時に1つへまとめます。

### 実測(同じ 1km のオオカミ・個人の補正なし・仲間 0〜3人)
| 人数 | 分配の前の正確な値(距離 + ボス) | 分配の後 | 整数(ボス) | 端数 | 帰還の整数化 → 受け取り |
|---|---|---|---|---|---|
| 1 | 26.464 + 46 = 72.464 | 72.464 | 46 | 0 | 72 |
| 2 | 26.463 + 46 = 72.463 | 36.231 | 23 | 0 | 36 |
| 3 | 26.488 + 46 = 72.488 | 24.163 | 15 | 0.333 | **24** |
| 4 | 26.379 + 46 = 72.379 | 18.095 | 11 | 0.500 | **18** |

- 4件とも、HUD の持ち帰り予定 = 結果の画面 = 実際に増えた所持 MILE でした。
- 単体の確認: 雑魚 121体 × 1 + ボス 301(基本 422)を 1〜4人で受け取りました。
  - 整数 + 端数 = 422 / 211 / 140.667 / 105.5 で、ちょうど一致しました(失われた物も、二重の物もありません)。

## 2. 中断・再開と報酬の整合性(修正)
### 今の決まり
- 再開はチェックポイントから走り直します。チェックポイントは次の時点です。
  - ランの始め(0m)
  - ボスの報酬を選び終えた所
  - 疾走の到着
  - ラスダンの YES
- **ラン中の状態も、すべてチェックポイントの時点へそろえます**:
  - 距離 / EXP / Lv / 順番待ちのレベルアップ
  - MILE と端数 / 預かり中のボスの EXP
  - カード / CPU の仲間の取ったカード / 撃破数 / HP / ボスの再戦プール
- 中断の保存(ホームへ戻る / 一時停止 / アプリの終了)は、記録の控え(走った距離・時間・デバッグ使用の印)だけを書き換えます。
- そのため、走り直しの区間で同じ敵 / ボスから報酬が二重に出ることはありません。
  - ボス戦の途中で中断した場合も同じで、ボス戦の前のチェックポイントからやり直しです(第1弾の「ボス戦中は保存を止める」は不要になったので外しました)。
- ボス戦の間に上がったレベルアップは、ボスの報酬の直後はまだ順番待ちです。その数も保存し、再開の後に1回ずつ出します(以前は再開で消えていました)。

### 確認(Windows、専用の保存ファイル)
- ソロ / CPU の仲間2人:
  1. 1km のボス(チェックポイント)
  2. 1.3〜2km で雑魚を倒し、EXP / カードを進める
  3. 2km のボスを倒して報酬の選択中に、ホームへ戻る
  4. CONTINUE
  - 結果:
    - 1km の時点の値に一致しました(距離 1000m・Lv・EXP・MILE e/b・端数・撃破数・カードの数・CPU の取ったカード)。
    - 順番待ちだったレベルアップは、1回だけ出ました。
    - 2km のボスを倒し直すと、1回分(46 / 15)だけ入りました。
- **報酬の選択中にアプリを止める**:
  - 報酬の選択中に OnApplicationPause → プロセスを強制終了 → 同じ保存ファイルで起動し直す → CONTINUE。
  - チェックポイントの値に一致しました。古い選択の画面は残りませんでした。
- **死亡**: 再開したランで倒れました。
  - 所持 MILE・ベスト・累計距離は変わらず、中断データは消え、確定もされていません。
- **ランの破棄**(ホームの「はじめから出発」= 中断データを消すだけ):
  - 所持 MILE・ベスト・累計距離は変わらず、中断データは消えました。

### 参考
- 累計距離(ProgressStats)は確定の時に「実際に走った距離」で足します。
  - 走り直しの区間は、実際に2回走った距離として数えます(報酬ではないので、今までどおり)。

## 3. ボスの EXP の計算の基準
- 基準は **今の Lv から次の Lv へ上がるのに必要な EXP の全体**(ExpToNext = 150 + 60 ×(Lv − 1))です。残りの EXP ではありません。
  - 撃破の直前の EXP のバーの位置では変わりません。
- 計算の順番:
  1. 基本 = max(100, ExpToNext × 割合)
  2. × 撃破の EXP のカードの倍率(EXP UP / EXPERIENCE BURST などを1つの枠に足して、曲線を1回通した値 = ExpMultKill)
  3. × 開発用の CARD TEST の倍率(通常は 1)
  - EXP の倍率はここで1回だけ掛けます。
- 割合は、第2弾で **関門の役割** で決めるようにしました(ボスの種類ではなく):
  - 1km の関門: 20% / 5km: 35% / 10km: 80% / ボスラッシュ: 80%
  - メカドラゴン・死神(特別): 120%(種類のまま)
  - 理由: 11km 以降の 1km の関門では、撃破済みの大ボスが再戦に出ます。種類で決めると毎km 大ボスの EXP(80%)が入っていました。
    - 例: 12km の 1km の関門で 984 EXP。疾走で 10km に着いてから4分で Lv15 → 25 と速すぎました。
  - MILE は今までどおり、ボスの種類と強さで決めます。
- 同じフレームに複数のボスを倒した時: 1体目で Lv が上がると、2体目は上がった後の Lv の必要量が基準になります(少しだけ多くなる)。

## 9. WANTED の賞金が HOST だけの理由(今回は確定しない)
- 賞金首は、敵の出現と同じく HOST の端末だけで決めて、HOST の端末だけが「どれが賞金首か」を覚えています(`ChallengeSystem.cs`)。
  - 賞金首であることは、JOIN へ送っていません。
- 賞金は「覚えている敵が倒れた時」に、HOST の端末で HOST に入ります。誰が倒しても HOST です。
- 賞金首の強さと賞金は、HOST のカード(WANTED のレベル)で決まります。
- 設計として決めた物ではなく、同期を作っていないための今の形です。
- 案: 撃破の知らせ(OpDeath)に「賞金首」の印と賞金を載せて、ほかの撃破と同じく人数で割って全員へ渡す。
  - 決まるまで、今の形のまま(マルチでは割らない)にしています。
