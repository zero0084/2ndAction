目的: Google Play の公開に要る「サーバーのデータの削除」を、development の本物のサービスで、削除 → 新しいプレイヤー → 再利用まで通す。
production には何もしていない(配置・Secret・テストデータの作成・変更なし)。

## 2. 削除の流れ(本物で通した順番)

試験用のプレイヤー D:
1. 匿名でサインイン(development)
2. 荒野街道・自然洞窟にランキングの記録を送る
3. コードネームを掲載し、変更する(omm_set_name)
4. 設定 → データの削除 → 自分の Player ID が表示される → 削除する
5. サーバーのデータの削除が成功(`server data deleted (cloud save 3, leaderboards 1)`)
6. その後で Authentication のアカウントの削除が成功
7. 管理側から読む: ランキング 4マップとも なし / Cloud Save なし / アカウント なし

順番は今までどおり「サーバーのデータ → 成功を確かめる → アカウント」。サーバーで失敗したらアカウントは消さない。

## 3. 新しい Player ID になること

削除の後に同じ端末で起動し直して:
- 起動しただけ: サービスの初期化もサインインもしない
- データ削除の画面を開いただけ: 「アカウントなし」。サインインの記録(session token)も作らない
- ランキングを初めて開いた時に、新しい匿名プレイヤーになる(削除前と別の ID)→ 記録を送れる・順位が出る
- その新しいプレイヤーで ONLINE PLAY(CREATE / FIND / JOIN / Relay)も使える
- さらにその新しいプレイヤーをもう一度削除 → 成功(削除 → 再生成 → 再利用 → 削除が繰り返せる)

## 4. 削除の失敗(本物のサービスで起こした)

開発版だけの試験の入口(`AccountDeletion.DebugFailOnce`、製品版には入らない)で、1回だけ失敗させた。

| 失敗 | 起こし方 | 画面 | サーバー | 端末の保存 | 再試行 |
|---|---|---|---|---|---|
| Cloud Code の失敗 | 無いスクリプトの名前を呼ぶ(サービスが NotFound で断る) | 「サーバーのデータを削除できませんでした」 | 何も消えない(記録・アカウントとも残る) | 変化なし | 削除のボタンがまた押せる |
| Authentication の削除の失敗 | サーバーのデータを消した後、アカウントの削除の直前にサインアウト(SDK が断る) | 「アカウントを削除できませんでした」 | サーバーのデータは先に消えている・アカウントだけ残る(=本人がもう一度消せる) | 変化なし | 同じ画面からもう一度 → 成功(残っていないサーバーのデータは「無い」で成功扱い → アカウント削除) |
| ランキングの削除(Admin API)の失敗 | 今回は起こしていない(Secret を壊すことになるため)。2026-10-20 に Secret が無い状態で本物で実行した時は「サーバーのデータを削除できませんでした」(`not configured`)・何も消えない・アカウントは残った | — | — | — | — |
| つながらない | 無い環境を指定(`-ugsEnv qa-missing`、前回の試験) | 削除へ進まない | — | 変化なし | — |

どの失敗でも、アプリは止まらず(ホームが動き、保存も書ける)、ゲーム本体はそのまま使える。

## 5. 他人のデータを削除できないこと(本物で確認)

- スクリプトは引数を1つも宣言していない(`module.exports.params = {}`)。Cloud Code は宣言していない引数をスクリプトへ渡さない(2026-10-20 に確認済み)
- 削除の対象は、呼び出しを認証された本人(`context.playerId`)だけ
- 試験: プレイヤー C2 が、D の Player ID を `playerId` / `targetPlayerId` / `id` / `player` の4つの名前で渡して削除を呼んだ → 消えたのは C2 自身の(空の)データだけ。D の記録・Cloud Save・アカウントは管理側から見て全部残っていた。別の組(J → G)でも同じ

## 6. ついでに見つけて直したもの

- **コードネームを変えると、ランキングのキャラ/オート/疾走の印が消えていた**(omm_set_name)。サーバーの記録を読む時に metadata を頼んでいなかった。頼むように直して development へ配置 → 変更後もキャラが残ることを確認。**production の omm_set_name も同じ問題がある**(production へは配置していない)
- 開発版の確認用の詳細(Detail)が、再試行で成功した後も前の失敗のまま残っていた → 実行のたびに消す
- プライバシーの自動試験が、試験のたびに development に空の匿名アカウントを1つ作っていた(試験が置く「送信待ち」を、ゲームが正しく送ろうとしてサインインしていた)→ 送られない環境名にした。作られていたアカウントは本物の削除の流れで消した

## 7. 試験用データの後始末

- 今回作った試験用のプレイヤー(D・E・G・C2・J・新しい D・プライバシー試験の1つ)は、すべて本物の削除の流れで消した。管理側から見て、ランキング・Cloud Save・アカウントとも なし
- 2026-10-20 の試験のプレイヤー(A・B・C と、直接書き込みの試験のプレイヤー)は、サインインの記録が手元に残っていなかったので本人としては消せなかった → **ランキングの記録だけ**管理側から消した(development)。アカウントと Cloud Save の `omm_runs` は development に残っている(Dashboard の Player Management から消せる)
- レジストリ:
  - 「前回レジストリへ残していた試験用の Sign-in 情報」は、今回の開始時点で本物の保存(One More Mile)にもう無かった(名前だけ確認、値は見ていない)
  - 今回の試験は別の名前の試験用ビルド(One More Mile Test)で行い、試験の前に控えたその鍵を最後に元へ戻した(控えと同一)。どちらの鍵にも Sign-in の情報は残っていない
  - 本物の保存の鍵は、試験の開始から終わりまで同一

## 10. 既知の問題・気づいたこと

- 配置の道具の「Secret の名前の一覧」は 404 で読めない(道具の問い合わせ先の問題。Secret が使えることは削除のスクリプトの成功で確認済み)
- 配置の道具はエディターのサインインを使う。Unity Hub が起動していないと「サインインしていない」で止まる(今回、Hub を起動して解消)。起動時の「Packages with Errors」の確認画面が出ると待ちになる
- この PC の本物の保存には、2026-10-20 の時点で production の匿名のサインインの記録(default)があったが、今は無い(いつ消えたかは不明。今回の試験は触っていない)。次に production で ONLINE/ランキングを使うと新しいプレイヤーになり、前の production の記録はそのまま残る

## 11. production へ反映する前に必要な作業(今回はしていない)

1. production 用のサービスアカウント(Leaderboards のスコアの削除の権限)と、production の Secret Manager への `OMM_ADMIN_BASIC` の登録(マスター)
2. production へ `omm_delete_player` と、直した `omm_set_name` を配置(マスターの確認の後)
3. production で、専用の試験プレイヤーで同じ流れ(作成 → 削除 → 管理側で確認)を通す
4. 通ったら `AccountDeletion.ProductionReady = true` にして製品版のアプリ内削除を有効にする(今は製品版はメールでの依頼を案内)
5. プライバシーポリシー・Play Console のデータセーフティの「削除の方法」を、アプリ内の削除ができる形に合わせて見直す
