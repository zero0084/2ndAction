## 1. 合成カードの説明と言語の切り替え — 修正済み
**原因の確認**
- 保存されるのはカードの ID(合成カードは能力一式のキー `v2|…`)・Lv・枚数だけで、説明文は保存されない(`OwnedCardsV1`。保存の処理は APK 395 から変わっていない)。説明はキーから毎回作り、今は日本語の元の文で持って表示の時に訳す → 過去に訳した説明が残ることは無い。
- **不具合**: デッキ編集を開いたまま(右上の歯車から)言語を切り替えると、一覧は書き直されるが、右の詳細(名前・能力の数値・説明)は前の言語のまま残っていた → `DeckEditUI.OnLocChanged` で詳細も書き直す。

**確認(試験 `-qaLocSwitch`、横 1280×720)**
- 前から持っていた合成カード 2枚(保存の形のキーを入れた物)+ 新しく合成で作った 1枚 × ja/en/ar/de/ta。
- 画面を開く → 閉じて開き直す: 同じ文、日本語の残り無し、言語ごとに変わる。合成の画面の詳細も同じ。
- 開いたまま en → de → ar に切り替え: 詳細が書き直され、新しく開いた時と同じ文。
- アプリを再起動(2回目の起動): 選んだ言語(de)のまま、説明は再起動前と同じ、能力・Lv・所持数は前後で同じ。
- 保存されたデータの中身: ID/Lv/枚数だけ(説明の文は入っていない)。
- 結果: 2回とも全項目合格(1回目は新しく作る合成カードの元のカードの指定を間違え、作り直して2回目で3枚とも確認)。
- 画像: `img/locswitch.jpg`(新しく作った合成カード: 日本語 → アラビア語)、`img/locswitch2.jpg`(ドイツ語: 開いたまま切り替えた直後 / 再起動の後)

## 2. 動的な翻訳の仕上げ — 修正済み
**部品の訳が無い時に実際に出る物(試験 `-qaLocFallback`、de/ar/en)**

| 場合 | 直す前 | 直した後 |
|---|---|---|
| 今の言語だけ部品の訳が無い | その部品は英語(数値はそのまま) | 同じ(英語) |
| 型(文全体)の訳が今の言語だけ無い | 英語の型 | 同じ |
| どの言語にも訳の無い部品(並び・「能力名 数値」・後ろの括弧) | 文全体が日本語のまま(数値は残る) | **訳せる部品は訳し、無い部品だけ元の文**(例: `Attack +10% / 未登録の効果 +3m`) |
| どの言語にも訳の無い文(型の形) | 文全体が日本語のまま(数値は残る) | 同じ |

**語順が言語で変わる文の見直し**

## 3. アラビア語・ペルシャ語の折り返し — 修正済み
**再現した所**: 長い文が枠の幅で自動に折り返す所すべて(右から左に並べ替えた後の文を左から切るので、1行目に文の最後が来ていた)。縦画面のデッキ/カード選択の説明・お知らせ・練習の説明・合成の結果・疾走の説明など。
**直し方(共通の描画処理)**
- `Loc`: 並べ替えた文 → 元の文を覚える。`Loc.RtlWrap` が、描く幅に入るよう「元の順で」語ごとに行を分けてから、1行ずつ並べ替える(`ArabicShaper.WrapForDisplay`)。色・太字・大きさのタグは行をまたいでも付け直す。
- IMGUI: `LocGUI.Label`(全画面の IMGUI の文字が通る所)と `UiScroll.Text` で、折り返す時だけ使う。
- uGUI: `RtlTextWrap`(右から左の言語の時だけ動く)。折り返す設定の Text で、幅に入らない並べ替え済みの文だけを置き換える。文が変わったフレームのうちに直し、回転で幅が変わった時も直し直す。訳をタグで囲んでつないだ文(カード選択の説明)も、タグの中の訳ごとに直す。
- **影響の範囲**: アラビア語・ペルシャ語の時だけ動く(他の言語は何もしない)。入る文・元の文が分からない文はそのまま。
**確認(試験 `-qaRtlWrap`、同じ版で修正を外した時と比べる)**: デッキの合成カード/長い説明・合成の予告/結果・お知らせ・疾走の説明・練習の説明・ラン中のカード選択を開き、uGUI の文字が自分で折り返していないか(= 行の順番が入れ替わっていないか)を数えた。

|---|---|---|---|
| 縦 486×1080 | アラビア語 | 自分で折り返した文字 8件 | **0件**(確認 287件、行に分けて並べ替え直した IMGUI 170回・uGUI 63件) |

- 画面の巡回(アラビア語・縦・全画面): 残ったのは試験が入れた見本の長い文(日本語と英語の混じった訳でない文)の2件だけ。
- 複数行・数字・括弧・色の書式タグの混ざる例(合成の予告と結果・カードの説明・お知らせ・デッキの詳細)を縦横で目で確認。`img/rtl_before_after.jpg`(左: 直す前 / 右: 直した後。練習の説明は直す前は1行目に文の終わりが来ていた)

## 4. 操作・戦闘の未確定項目
### 4-1. 魔法使いの TouchFlick — 原因確定: 試験側(ゲームの入力は失われていない)
試験は、画面の指と同じ経路(指を置く → 動かす → 離す、`PlayerController.UpdatePointerInput`)と、技を直接呼ぶ入力を比べている。食い違いの原因はどれも試験側:
1. 魔法使いの上下は待ち時間だけ入り「技の始まり」に数えていなかった + 前の操作の高さ(段)が残り、上限/下限で段が変わらない回があった(ログ: `touch moves 1 | inject moves 0`、段 3→上限)。→ 数え方を直し、毎回段を 0 にそろえる。
2. 途中のレベルアップの演出で時間が止まり、その間の指の操作はゲームが意図して読まない(停止中の指は操作にしない作り)。試験はその間も指を動かしていた(ログ: `[LevelUpPresentation] Gameplay resumed` の直後のケースだけ `touch []`)。→ 試験中は経験値を止め、停止中は操作を始めない。
3. 地上の下フリックは「入力が届いたフレームに空中なら急降下」の作りで、指の速さで届くフレームが1〜7フレーム違い、地面の起伏で接地が変わることがあった → 届いたフレームの接地を記録し、違った時は別に数える(今回は 0件)。
**確認**: 指の経路で 180ケース(魔法使い 40・空中 4キャラ 80・地上 3キャラ 60)すべて直接の入力と同じ結果。

### 4-2. 洞窟・高速時の空中コンボ — 原因確定: 跳びは試験側、天井はゲーム側を修正

### 4-3. リヴァイアサンの BREAK 中の引き寄せ — 原因確定: 跳びは試験側、+ ゲーム側の1点
- 引き寄せ自体は正常(BREAK の長さ・回復・撃破・報酬・画面内の判定はすべて合格)。

## マスターに実機で確認していただきたいこと
1. **アラビア語/ペルシャ語(縦画面)**: カード選択の説明・デッキ編集のカードの説明・練習の説明・お知らせ・疾走出発の説明が、1行目から読める順に並んでいるか。回転させた後も崩れないか。
2. **言語の切り替え**: デッキ編集を開いたまま右上の歯車から言語を変えると、右の詳細(合成カードの能力の行・説明)もその言語に変わるか。アプリを閉じて開き直しても同じか。
3. **合成**: 異なるカードの合成の結果「メイン側/素材側(… Lv.1): 継承成功/継承失敗」と演出中の見出しが、英語で Inherited / Not inherited になっているか(他の言語も対になっているか)。
4. **BREAK**: 大きなボス(リヴァイアサンなど)を BREAK させて攻撃した時、ボスが一瞬前へ滑らないか(高速時)。
5. **洞窟の高速の空中コンボ**: 打ち上げた敵が天井にめり込まないか、急に下がって見えないか。
6. **マルチ(LAN)**: 部屋を作る → もう1台で参加 → 抜ける、で通知が部屋の名前に重ならず「P2 が…」と出るか(縦横)。
7. **脱出後の FAILED が再発した場合**: その時に `escape_trace.txt`(アプリのデータの場所)か logcat の `[Escape]` をいただければ、同じランの流れを追えます。
