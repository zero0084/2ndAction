# 死神のラン中に、脱出の演出の後で敗北になる件(2026-10-24)

## 原因(確定)

長押しが完了しても、`Win()` を呼ぶまで成功が確定していませんでした。

以前の流れ(`PlayerController.DoFinishSequence`):

1. 長押しの完了 → 被弾の禁止(PresentationDamageLock)を ON にして、成功の演出を始める
2. 減速(0.22秒)→ 終わりのポーズと余韻(1〜2秒。100km 以降は 2秒)。プレイヤーはその場で止まっている
3. **演出の最後で被弾の禁止を OFF** → 画面の切り替え(暗転)を始める
4. 暗転が画面を覆った所(約0.25秒後)で `Win()`

3〜4 の約0.25秒の間に死神の大鎌が当たると、`ReapPlayer` → 敗北が先に確定します。その後の `Win()` は「もう終わっている」で何もしませんでした。

- 止まっている間に死神が追いついて大鎌を構えるので、100km 以降ではこの間にちょうど当たりやすい状態でした。
- 2 の間の一撃は禁止で防がれていましたが、`ReapPlayer` は防ぐ前に HP を1撃分まで減らしていました(結果には影響なし)。
- ほかの画面の切り替えの最中だと、`PlayTransition` が何もせず `Win()` が呼ばれない穴もありました(今回まとめて直しました)。

**以前の動きの再現**(`-qaEscape -escLegacy 1`、99,900m から本来の流れで死神が出る場面。f = フレーム、t = 秒):

| f | t | できごと |
|---|---|---|
| 5657 | 92.29 | 長押しの完了 / 成功の演出の開始 |
| 5786 | 94.53 | 演出の終わり → 画面の切り替え(ここで被弾の禁止が外れる) |
| 5794 | 94.67 | **死神の一撃で敗北が確定**(Reaper:Eldest)/ RESULT(敗北) |
| 5800 | 94.80 | `Win()` は無視(もう終わっていた) |

## 直し方

**長押しが完了した時点で、成功を確定します**(`GameManager.TryConfirmEscape`、新しい `GameManager.Escape.cs`)。

- 敗北が先に確定していれば、成功を確定せず、演出も始めません。
- 同じフレームでは、先に起きた方に決まります。結果と演出は食い違いません。
  - プレイヤーの処理(長押し)は死神の大鎌の処理より先に動きます。そのため、同じフレームの長押しの完了は成功になります。

成功の確定の後は、次のようにしました。
- 被弾・死神の一撃・落下・マルチの脱落の知らせで、敗北になりません(受けなかった分は記録に残ります)。
- 死神はその場で止まります(追跡・大鎌・接触の判定を止めます)。
- 距離・EXP・MILE・撃破の報酬・走った時間は増えません。確定した時の値で記録します(演出の減速で進んだ分も数えません)。
- 被弾の禁止は最後まで外しません。演出の最後には必ず `Win()` を呼びます(ほかの切り替えの最中なら直接呼びます)。

長押しの途中など、成功の確定の前の危険は今までどおりです(長押しの途中の死神の一撃・落下・被弾は効きます)。

**記録**: 長押しの完了・成功の確定・演出の開始・演出の終わり・敗北の確定・`Win()`・RESULT の表示を、`[Escape] f=フレーム t=時刻` でログに出します(実機のログでも順番を追えます)。

## 確認(Windows の開発版、専用の保存)

`-qaEscape`(新規)。荒野街道、無敵なし。死神は 3km 付近で出し、warp100k だけ 99,900m からの本来の流れです。

| 場面 | 修正後 | 以前の動き(比較) |
|---|---|---|
| before: 長押しの完了の0.2秒前に死神の一撃 | 敗北(成功の演出なし・報酬なし) | 敗北 |
| after: 長押しの完了の0.2秒後に一撃の予定 | **成功**(死神は止まり、一撃は来ない) | 成功(一撃は禁止で防がれた) |
| samereap: 同じフレームで 一撃 → 長押しの完了 | 敗北(成功は確定しない・演出なし) | 敗北 |
| sameescape: 同じフレームで 長押しの完了 → 一撃 | **成功**(一撃は無視) | 成功 |
| transition: 最後の暗転の間に一撃 | **成功**(一撃は無視) | **敗北(演出の後に負ける)** |
| during: 死神のすぐ前で脱出して、止まっている間に追いつかれる | **成功** | 成功(今回はたまたま間に合った) |
| warp100k: 100km 以降の本来の死神の流れ | **成功** | **敗北(実機で起きたこと)** |
| normal2k: 2,000m の通常の脱出(死神なし) | 成功 | 成功 |

**成功の時に確かめたこと**(全部の成功の場面)
- 結果の確定は1回だけ(FinishRun ×1)。
- MILE は1回だけ入る(財布の増え = このランの MILE、例: 100km で +1,000)。
- BEST は脱出した距離。正式な記録の確定(ランキングの対象の判定を含む)は1回。
- 確定の後に距離と MILE が増えていない(確定の時の値 = 最後の値)。

**敗北の時**: 財布・BEST は変わらず、正式な記録もありません。

**結果**: 修正後 0件の失敗、例外 0件。以前の動きでは transition / warp100k の2場面で、成功の演出の後に敗北になりました。

**既存の試験**
- 死神に捕まった後の流れ(`-qaReaperDeath`、荒野街道10場面): 捕まる → 即死 → RESULT → ホームは 10/10 で止まりませんでした。
- 「ホームへ戻った直後の時間の速さ」の確認だけが失敗していました。RESULT は時間を止める仕様(10-23 から)で、読み直した直後はまだ 0 のためです。少し待って見るように試験を直しました(再試験の結果は下の追記)。
