# 開発版と製品版の Unity Gaming Services の環境の分離 — 2026-10-14

開発版・試験用のビルドの記録が、公開のランキング(`production`)へ載らないようにしました。
**本物のサービスでの確認は、「開発版が production へ切り替わらない」ことだけです**(下の「確認の結果」)。
`development` 環境はまだ Dashboard に無いので、開発版のオンライン機能(ONLINE PLAY・ランキング)は、作るまで「使えない」になります(LOCAL PLAY はそのまま遊べます)。

- 実装: `Net/UgsEnvironment.cs`(環境の決め方)、`Net/OnlineServices.cs`(初期化)、`Online/Leaderboard.cs`(送信待ちの環境)、`Online/UgsLeaderboardBackend.cs`(送信の直前の確認)、`Tools/ugs/cloudcode/omm_submit_run.js`(サーバーの確認)
- 確認用(開発版だけ): `QaSweep.UgsEnv.cs`(`-qaUgsEnv`)

## 1. 環境の決まり方

| ビルド | 使う環境 | 変えられるか |
|---|---|---|
| 製品版(Development Build でない) | `production` | 変えられない(起動引数も読まない) |
| 開発版 / Editor | `development`(既定) | `-ugsEnv <名前>` で別の**開発用の**環境(例 `staging`)へ。**`production` は選べない**(指定しても無視して `development` のまま。ログに `ignored -ugsEnv production` と残す) |

- Android の開発版は `qa_args.txt` の `-ugsEnv` も読みます。
- 環境は起動の時に1回だけ決め、UGS の初期化もこの環境で1回だけ行います。
- **選んだ環境が無い/つながらない時**:
  - その環境のまま「ONLINE SERVICE UNAVAILABLE」になります。
  - **`production` へ自動で切り替えることはしません**(もう一度試しても同じ環境)。
  - 開発版の表示/ログ: `UGS environment 'development' is missing (create it in the Dashboard; production is not used instead)`。
- **UGS を初期化するのは `OnlineServices` の1か所だけ**です(Auth / Sessions(Lobby)/ Relay / Leaderboards / Cloud Code はすべてこの初期化の環境を使います)。
  - 他の所が先に環境を指定せずに初期化していた場合は、環境を確かめられないので使いません。今のところ、そういう所はありません(課金の SDK は初期化しません)。

## 2. ランキングの送信待ちの扱い

- 送信待ち・資格のある自己ベストの1件ずつに、**作った時の環境(`env`)**を付けます。
- **送るのは、今の環境で作った物だけ**です。次のどれも同じです。
  - 確定した時の送信
  - ホームでの自動の再送(30秒ごと)
  - 手動の「再送」
  - 参加した時の、それより前の自己ベストの投稿
- 別の環境の物、環境を付ける前の版(APK 309 以前)の物(`env` が空):
  - **送らずに残します**。消しません、別の環境へ付け替えません。
  - 開発版の表示では `held`(保留)の件数として出します。
- 自己ベストは「マップ × 環境」ごとです。開発用の環境の長い記録があっても、別の環境の記録の送信は止まりません。
- **開発版 → `production` の送信は三重に止めます。**
  1. 環境: 開発版は `production` を選べない。
  2. 送信の処理: 開発版が `production` を使っていたら、何も送らない(`send blocked`)。
  3. 送信の窓口(`UgsLeaderboardBackend.Submit`): 今の環境で作った物でなければ、通信する前に止める。止めた物は「失敗」扱いで、送信待ちに残す。
- **サーバー(`omm_submit_run.js`)の確認**:
  - 端末は `buildKind`(`release` / `dev`)と `env` を送ります。
  - `production` 環境のスクリプトは、`buildKind = release` かつ `env = production` の物だけを書きます。
  - それ以外(開発版、`buildKind` を送らない古い版)は `rejected: dev build` で書きません。
  - ※ Cloud Code の `context.environmentName` を使っています。**本物のサービスでは未確認**です。渡らない場合は、この確認を飛ばしてログに残します。
- 引き継ぎ(データの書き出し・読み込み)では、ランキングの送信待ちは今までどおり運びません(端末ごと)。

## 3. 今の環境の表示

- 開発版の DEBUG の画面の上に、`UGS env: development (dev build default)  ranking pending N / held M` を出します(無視した指定があればそれも)。
- 開発版のランキングの画面に、`DEV  UGS env: development (not the public ranking)` を出します。
- ログ:
  - 起動時: `[Ranking] UGS environment 'development' (dev build, …); N pending for this environment, M held …`
  - 初期化: `[ONLINE] UGS Initialize (UGS environment '…')`
  - 失敗: `Service error (…, environment …)`
  - 送信: `sent … to 'development'`
  - 止めた時: `send blocked …`
  - 秘密の値(トークン等)は出していません。

## 4. 環境ごとに分かれる範囲

| サービス | 環境で分かれるか | このゲームでの影響 |
|---|---|---|
| Sessions(Lobby) | 分かれる(部屋の一覧は環境ごと) | 開発版の部屋は製品版の一覧に出ない |
| Relay | 分かれる(割り当ては環境ごと) | 同上 |
| Leaderboards | 分かれる(表の設定も記録も環境ごと) | `development` に同じ名前の表を作る必要がある |
| Cloud Code | 分かれる(スクリプトは環境ごとに配置) | `development` にも2本を配置する必要がある |
| Cloud Save(送信済みの記録 `omm_runs`) | 分かれる | 重複の判定は環境ごと |
| Access Control | 環境ごとに設定 | `development` にも同じ禁止を入れる |
| Authentication(匿名のプレイヤー ID) | **未確認**。プロジェクト共通か環境ごとかは本物で確かめていない | 匿名なので、どちらでも記録が混ざることはない(表が環境ごとのため) |

※ この表は Unity の仕組みの理解に基づきます。**本物のサービスでは、`development` が無いと初期化できないこと以外は未確認**です。

## 5. マスターが Dashboard で行う作業(development 環境)

値はすべて今のコードに合わせています。**秘密の値(サービスアカウントのキー等)をチャットやファイルで渡す必要はありません**。プロジェクト ID と環境の名前はアプリに入っています。

### 5-1. 環境を作る
- Unity Cloud Dashboard → プロジェクト **One More Mile**(ID `8568059a-fddf-40c3-8e3f-53c041143997`)→ Project settings → Environments → Add environment
- 名前: **`development`**(英小文字。開発版の既定と同じ名前。違う名前にした場合は、その名前を知らせてください)
- 以下はすべて、Dashboard の上部の環境の切り替えを **`development`** にしてから行います(production を触らない)。

### 5-2. Leaderboards(4つ)
| ID(正確に) | 並び順 | 更新の種類 | リセット | バケット / ティア |
|---|---|---|---|---|
| `omm_best_wasteland_road` | 降順(高い方が上) | Keep latest score | なし | なし |
| `omm_best_natural_cave` | 同上 | 同上 | なし | なし |
| `omm_best_sky_corridor` | 同上 | 同上 | なし | なし |
| `omm_best_last_corridor` | 同上 | 同上 | なし | なし |

- 表示名は自由です(ID だけが一致している必要があります)。
- 「Keep latest score」にする理由: 自己ベストかどうかは Cloud Code が判定します。表示名の変更の時も、同じ距離で書き直すためです。

### 5-3. Cloud Code(JavaScript のスクリプト 2本)
最新版のファイル: `Tools/ugs/cloudcode/omm_submit_run.js`(2026-10-14 版。`buildKind` / `env` の確認入り)と `Tools/ugs/cloudcode/omm_set_name.js`。

- 作り方:
  1. Cloud Code → Scripts → Create script(JavaScript)。
  2. 名前は下の表のとおり。
  3. ファイルの中身を全部貼る。
  4. パラメータを下の表のとおり登録する。
  5. **Publish(公開)**する。Publish しないと呼べません。

### 5-4. Access Control(プレイヤーがランキングへ直接書くのを禁止)
ファイル: `Tools/ugs/access/omm_leaderboards.ac`。中身は次の1件です。

| 項目 | 値 |
|---|---|
| Sid | `deny-player-leaderboard-writes` |
| Action | `Write` |
| Effect | `Deny` |
| Principal | `Player` |
| Resource | `urn:ugs:leaderboards:/v1/projects/*/leaderboards/*/scores/players/*` |
| Version | `1.0.0` |

- Dashboard に Access Control(プロジェクトのアクセスポリシー)の画面があれば、そこに上の内容で登録します。
- 画面が無い場合は、UGS CLI を使います。
  1. マスターの PC のターミナルで `ugs login`(キーはご自身で入力。**チャットに貼らないでください**)。
  2. `ugs config set environment-name development`
  3. `ugs deploy Tools/ugs/access/omm_leaderboards.ac`
- Cloud Code はサービスの権限で書くので、この禁止の影響を受けません。

### 5-5. Multiplayer(ONLINE PLAY 用。Sessions = Lobby + Relay)
- `development` で Lobby と Relay が有効になっているか確認してください(環境ごとに有効にする画面があれば有効に)。
- 追加の設定(部屋の種類など)は要りません。アプリが `omm-online` という種類で作ります。

### 5-6. 終わったら知らせてほしいこと(これだけで接続の試験を始められます)
- 「development を作り、5-2〜5-5 が終わった」こと。
  - 環境の名前を `development` 以外にした場合は、その名前。
  - Access Control をどの方法で入れたか(画面 / CLI)。
- できなかった項目があれば、その項目。
- **キー・トークン・パスワードなどは不要です。送らないでください。**

### 5-7. 知らせてもらった後にアイリーンが行う確認(本物のサービス、development だけ)
| 確認 | 方法 | どこの結果か |
|---|---|---|
| 認証(匿名サインイン)と環境 | `-qaUgsLive`(専用の保存ファイル) | サーバー |
| ランキングの送信(ソロ)と取得 | 同上 | サーバー |

## 6. 確認の結果(Windows の開発版、専用の保存ファイル + 模擬サーバー)

`-qaUgsEnv`。本物のサービスへは書いていません。

| 確認 | 結果 |
|---|---|
| 開発版の既定の環境 | 合格: `development` |
| `-ugsEnv production` を付けて起動 | 合格: 無視して `development`。ログと DEBUG の画面に「無視した」と出る |
| `-ugsEnv staging` | 合格: `staging`(開発用の別の環境は選べる) |
| 送信待ちに「分ける前の物 / production の物 / 別の環境の物 / 今の環境の物」を入れる | 合格: 送れる 1件、保留 3件 |
| 通信失敗 → 再送 | 合格: 失敗した物は残り、再送(ホームの自動の再送を含む)で今の環境の物だけが届く |
| 保留の3件 | 合格: 消えない・付け替えない・送らない(模擬サーバーに届かない) |
| 参加し直し(参加より前の自己ベストの投稿) | 合格: 別の環境の自己ベストは送らない |
| 別の環境の長い自己ベストがある時の、今の環境の記録 | 合格: 今の環境の新記録として送る |
| 送信の窓口に production の物を渡す | 合格: 通信する前に `blocked`(UGS の初期化もしない) |
| **本物の UGS の初期化**(読み書きなし、専用のプロフィール) | 合格: `development` が無いので失敗(`UGS environment 'development' is missing …`)。もう一度試しても `development` のまま。**production へは切り替わらない** |
